## 2. 实际修改

### P0-1：多进程提交幂等

- `sqlite_repository.py` 增加可重入事务上下文，使用 `BEGIN IMMEDIATE` 在读取幂等键前取得数据库写事务；唯一键沿用 `records(collection, item_id)` 主键。
- `exercises.py` 将“再次检查幂等键、目标状态检查、判分、掌握度更新、计划重排、错题、轨迹、提交记录”放在同一事务中完成。占位由数据库写事务承担；失败时回滚，不留下半完成提交。
- 新增请求指纹。同一账号、题集和幂等键重放相同答案/目标返回已有结果；改交其他答案或目标返回 409。旧记录没有指纹时保留兼容行为。
- 后台解析回写回调只在提交事务成功后登记，避免回调抢在提交落盘前完成。
- `process_lease.py` 对 JSON 数据文件持有操作系统文件锁，第二个 JSON 服务进程明确报错并提示切换 SQLite。进程结束后由操作系统释放占用；锁文件本身可以保留。
- JSON 仓储读写增加深复制，防止调用方通过嵌套对象引用绕过条件更新。

### P0-2 / P0-3：解析并发限制与安全补回

- `review_jobs.py` 提供每进程共享解析池，默认 4 个任务运行、8 个排队。队列满直接使用确定性解析，并记录 `queue_full`。
- 默认等待解析 2 秒，超过预算后继续确定性判分、落盘和返回；日志记录 `wait_budget`。该 2 秒仅为解析等待预算，不是整个 HTTP 请求的硬上限。
- 后台结果按 submissionId、reviewToken 和原始记录快照条件更新，仅将 fallback 解析升级为 llm，不重新计分、更新掌握度或重排计划。
- 错题本仅在账号归属相同且完整记录未变化时更新解析；已删除、手工修改、后续练习、重建记录或重复回调不会被旧结果覆盖。
- 初次响应不自动推送新解析，客户端重放原提交可读取更新。后台任务为进程内任务，服务重启后不恢复；已落盘成绩和兜底解析保留。

### P1-1 / P1-3 / P2-1：模型预算、重试、连接复用与观测

- 新增 `llm_runtime.py`，文本、识图、出题、逐题解析、工作流决策和 Embedding 统一接入。
- 关闭 SDK 隐式重试；仅 429、500、502、503、504 最多重试一次。0.1 秒退避、排队及请求耗时计入总预算，认证和参数错误不重试。
- 调用运行层每进程最多 8 个任务运行、16 个排队。调用方超过墙钟预算即返回失败/降级；无法强制停止已经运行的底层网络调用，但不会无限创建后台线程。
- 按 base_url、Key 指纹、timeout 和 retry 配置缓存客户端，最多保留 8 组。请求级 timeout 直接传入 SDK 方法，不为每次请求重新构造 OpenAI 客户端；使用中的连接不会被缓存淘汰提前关闭。测试可显式清缓存。
- 每次逻辑调用记录 JSON 指标：request_type、model、elapsed_ms、http_status、tokens、finish_reason、retries、fallback_reason。未获得的状态或 token 为 null，不伪造数值。
- 日志不输出 Key、完整题目、模型响应、用户身份或异常正文；工作流另记录模型决策/确定性回落及原因。

### P1-2：五分钟出题缓存

- `exercise_cache.py` 实现进程内有界缓存，TTL 300 秒、最多 256 组，并按仓储、账号、知识点、题量及资料版本建立键。
- 通用生成题和资料题均接入缓存；读取时核对题目仍存在、归属和内容一致，并检查排除列表及交卷使用记录。
- 交卷事务同时记录 `exercise_usage`，已提交的题不再从短期缓存复用。资料删除、重新解析、正文哈希变化或出处校验失败时不复用旧资料题。
- 缓存不跨进程共享，也不承诺不同 worker 同时首次进入只发生一次出题。测试验证同知识点第二次进入低于 1 秒及账号隔离。

### P1-4：决策超时配置

- 新增 `LLM_DECISION_TIMEOUT_SECONDS`，默认 8 秒，且不超过 `LLM_TIMEOUT_SECONDS`。
- 决策不再每次新建单线程执行器，改用统一有界运行层。模型异常、JSON 无效及不适用决策均有可区分的 fallback 日志。

### P2-2：可验证健康状态

- `GET /api/agent/health` 保持被动，不产生模型费用。新增 `configured`、`verified`、`checkedAt`、`verificationReason`；保留 `llm_ready` 为配置状态的兼容别名。
- 登录用户显式 `POST /api/agent/health` 才执行最小文本模型探测，每进程最多每 60 秒一次，结果缓存 300 秒；未验证、过期或 Key/地址/模型变化时 verified 为 null。
- 主动探测只代表当前文本模型，不代表识图、Embedding 或所有业务链路可用。
- 两份 OpenAPI 同步补充可选字段及 POST 方法；仍为 43 条路径，版本保持兼容的 `api-contract-v0.3`。

### 补齐实际基线中的 Embedding、模型默认值与 PDF 差异

- Embedding 每批最多 10 条；查询加 200 个切片共 201 条，需 21 批，所有批次共享整次编码预算。校验 index、向量数量、维度及有限数值；任一批失败即诚实降级。
- 默认文本 `qwen-plus`、识图 `qwen-vl-max`；决策允许独立配置。更新 `.env.example`、README 和启动说明，没有改写本机 `.env`。
- PDF 优先 `pymupdf`，不可导入时兼容 `fitz`，保留 pypdf 回退及无效 PDF 的明确失败处理。新增真实有效 PDF 的生成、HTTP 上传、正文提取、切片及检索回归。

### P2-4：保留策略与写盘治理
