## 2. 实际修改

### P0-1：多进程交卷幂等与原子事务

- SQLite 增加可重入事务上下文，使用 `BEGIN IMMEDIATE` 将幂等检查、目标状态检查、判分、掌握度更新、计划重排、错题、轨迹和提交记录写入放在同一个事务中。
- 提交记录使用已有唯一主键约束；失败回滚，不发布半完成的学习状态。
- 新增请求指纹：同一幂等键重放相同答案及目标返回原结果；改交其他答案或目标返回 409。旧记录没有指纹时保持兼容行为。
- 后台回调仅在提交事务成功后登记，避免解析先完成而提交尚未落盘。
- JSON 后端增加操作系统文件占用检查，只允许单个服务进程使用；多 worker 必须切换 SQLite。JSON 嵌套对象读写增加深复制，避免外部引用绕过条件更新。

### P0-2：解析并发与队列有界

- 新增共享解析线程池，默认每进程最多 4 个任务运行、8 个排队。满载直接使用确定性解析，并记录降级原因。
- 默认等待解析 2 秒，超时后继续确定性判分、保存结果并返回 fallback。该预算只限制解析等待，不包含判分、数据库写盘、获取提交锁和计划重排。
- 模型运行层另设每进程最多 8 个任务运行、16 个排队，避免网络调用超时后无限创建后台线程。

### P0-3：慢解析安全补回

- 后台成功结果按 submissionId、reviewToken 和原始记录快照条件更新，仅将 fallback 解析升级为 llm，不重复计分、增加掌握度或重排计划。
- 错题本仅在账号一致且完整记录未变化时补回；已经删除、手工修改、后续练习或重建的记录不被旧任务覆盖。
- 重复回调不破坏数据，重放原提交可以读取已补回的解析。初次响应不自动推送新内容，客户端需再次读取或重放。
- 后台任务为进程内任务，服务重启后不恢复；已落盘的成绩及兜底解析保留。

### P1-1 / P1-3 / P2-1：统一模型运行层

- 文本、识图、出题、逐题解析、决策和 Embedding 接入统一运行层。
- 固定关闭 SDK 隐式重试；仅 429、500、502、503、504 最多重试一次，认证及参数错误不重试。排队、0.1 秒退避和请求耗时计入总预算。
- 调用方超过墙钟预算立即失败或降级；已经运行的底层网络调用无法强制终止，但后台资源数量受上限约束。
- 客户端按 base_url、Key 指纹、timeout、retry 配置缓存，最多 8 组。相同配置连续调用复用客户端及连接；使用中的连接不会因淘汰而提前关闭，测试可显式清缓存。
- 每次逻辑调用记录 request_type、model、elapsed_ms、http_status、tokens、finish_reason、retries、fallback_reason；缺失信息保留 null。
- 日志不记录 Key、完整题目、模型响应、用户身份或模型异常正文。工作流日志可区分模型决策与确定性 fallback。

### P1-2：短期出题缓存

- 通用生成题与资料题接入 5 分钟缓存，每进程最多 256 组，按仓储、账号、知识点、题量和资料版本区分。
- 命中时核对题目仍存在、归属及内容一致，检查排除列表和交卷使用记录。已提交、明确排除、删除或变化的题不复用。
- 资料重新解析、正文哈希或出处变化时不复用旧资料题；读取及保存时保留原有来源校验。
- 缓存不跨 worker 共享，不承诺多个 worker 同时首次进入只发生一次模型调用。

### P1-4：决策预算与模型配置

- 新增 `LLM_DECISION_TIMEOUT_SECONDS`，默认 8 秒，且不超过 `LLM_TIMEOUT_SECONDS`；决策复用有界运行层，不再每次新建执行器。
- 默认文本及决策模型为 `qwen3.8-flash`，识图为 `qwen3-vl-plus`；显式环境配置优先。
- DashScope 结构化短任务默认关闭思考模式，保留显式开启开关；其他兼容供应商不发送该扩展字段。

### P2-2：可验证健康状态

- `GET /api/agent/health` 为被动查询，不产生模型费用。新增 configured、verified、checkedAt、verificationReason；旧 llm_ready 保留为配置状态的兼容别名。
- 登录用户显式 `POST /api/agent/health` 才发起最小文本模型探测，每进程最多每 60 秒一次，缓存 300 秒。未验证、过期或 Key/地址/模型变化时 verified 为 null。
- 文本模型探测不代表识图及 Embedding 均可用。两份 OpenAPI 同步更新，保持 43 条路径和兼容版本 `api-contract-v0.3`。

### Embedding 与 PDF 处理

- Embedding 每批最多 10 条，查询加 200 切片共 201 条，分为 21 批；所有批次共享整次编码预算。校验批次 index、数量、维度及有限数值，任一批失败诚实降级。
- PDF 优先使用 pymupdf，兼容 fitz 导入回退，保留 pypdf 回退和无效 PDF 的明确失败处理。
- 保持 `pymupdf>=1.24.0,<2` 约束，本次锁定及验证版本为 1.28.2；真实有效 PDF 已覆盖生成、HTTP 上传、提取、切片和检索。

### P2-3：依赖锁定与干净环境复验

- `requirements-lock-py312.txt` 锁定 32 个直接及传递依赖，普通 requirements.txt 引用相同约束。
- 新建 `.venv-clean-sync`，Python 3.12.10，未启用 system-site-packages，按锁定清单安装并运行全量测试。
- 核对全部锁定版本，pip check 无冲突；保留 JUnit、freeze 和验收摘要。

### P2-4：保留策略及写盘治理

- 新增 `retention.py` 和 `tools/retention_repository.py`。默认 dry-run，显式 `--apply` 才执行；本批仅对合成测试数据预览。
- 按账号规划：traces 90 天/1000 条，submissions 180 天/1000 条，exercise_usage 7 天/5000 条；错题候选 365 天/1000 条，但未解决错题保留。历史对话按账号 90 天且最多 50 条。
- 活动目标引用、提交引用的轨迹、没有可靠时间或归属的记录保守保留，因此数量限制不是强制删除关联数据的硬上限。
- 仓储清理使用一次事务或批量发布。工具用于停服维护，history 与仓储属于独立文件，不宣称跨文件原子事务。
- 多 worker 使用 SQLite；现有 JSON 库应先停服、备份、迁移并逐条验证后再切换，不自动改用空库。
- 打包排除虚拟环境、项目内缓存、进程锁及私有运行配置。
