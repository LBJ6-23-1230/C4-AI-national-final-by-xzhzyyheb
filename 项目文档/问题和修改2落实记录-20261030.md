# 问题和修改2落实记录

根据用户提供的附件，在当前项目中落实错题本、知识点出题和聊天入口三类修改。附件原文件未改动。

## 错题本

- 每个知识点题组顶部仅保留一个“修改所属科目”入口。点击后进入多选模式，圆圈表示选中状态；支持全选、取消全选、单独勾选和取消。确认页只提交所选题目的 ID，每批最多100题，超过时有提示。
- 归类成功后保留知识点层级，进入新科目下的同一题组。题目卡片统一显示“开始刷题”和“移除”，不再按有无结构化选项分流到“查看题目”。
- 同一题组的全部题目都参与逐题练习，包括拍照收藏的题目。选项题提交后展示判分和解析；答案尚未核对的拍照题支持填写解题过程，提交后显示参考解析，不虚构正确次数或掌握度。
- 只有完成整组题目后才出现“同类练习”。该入口显式请求大模型生成新题，排除本轮原题 ID，并沿用标准交卷、评估证据及掌握度更新链路。
- 科目重分类会保留用户的学习目标记录。因此，即使最后一道原题在第三次答对后自动移出错题本，完成页仍可进入该科目的同类练习。不同科目的同名知识点分别记录掌握度。
- 补齐返回键的层级处理和迟到响应保护，提交失败后可在原题上重试。

## 知识点出题

- 导入或拍照得到的知识点可能使用独立 ID。现在允许同一课程内按知识点名称精确匹配固定题库，题目绑定回所选知识点 ID 后再判分，结果可正确回写画像。
- 课程筛选同时读取当前用户保存的可判分题目；生成题先绑定课程和知识点，再保存和缓存，避免缓存元数据失配。
- 重分类后的错题目标可以直接用于生成同类题，保留原科目的历史分数。
- 新增 `forceGenerate` 查询参数，表示明确生成新一组题目，跳过已有题库与生成缓存；前端不会用旧缓存掩盖本次生成失败。
- 生成失败和模型未配置分别给出可操作的提示，不返回无关知识点题目冒充成功。

当前项目后端 `.env`、进程环境和 Windows 用户/系统环境均未配置 `DASHSCOPE_API_KEY`。真实模型出题仍需在本机后端配置该变量并重启。测试采用受控模型替身验证调用及交卷回写，未声称已经完成真实模型调用。

## 聊天入口
