# 知学 Mate · UI V2 设计契约（DESIGN.md）

> 适用范围：`app/entry` 下的 ArkTS 页面与组件（HarmonyOS 6.1.1 / API 24）。
> 素材来源：`项目文档/UI-V2-20261103/参考图/`（15 张、60 屏视觉提案，以下简称「提案」）。
> 本文是**约束**，不是灵感板。实现时可以少做，但不能偏离这里的取值。
> 标注`〔推断〕`的条目是根据参考图与现有代码推算的，未逐像素核对。

---

## 1. Visual Theme & Atmosphere

**主题：可核验的学习工作台（verifiable study workbench）。**

- 观感目标：像系统级工具，不像作品集。信息密度高、层级清楚、装饰极少，一屏能回答「我现在该做什么、依据是什么」。
- 三条气质关键词：
  1. **证据感** —— 每个结论旁边都有来源（课程 / 题号 / 原文页码 / 更新时间），而不是一句 AI 口吻的断言。
  2. **克制** —— 一屏一个主色、一个主按钮、一个大数字。颜色只用来表达状态，不用来表达气氛。
  3. **可扫读** —— 评委/用户在 3 秒内抓到「标题 → 状态 → 下一步」，靠字号与留白分层，不靠阴影与卡片堆叠。
- 与当前实现的差别（这是本次要改的）：现在的主页面是「26vp 双行问候 hero + 大圆角卡片 + 大量留白」（`ChatMain.WelcomeBlock`），首屏有效信息密度约为提案的 1/2；详情页正文字号偏大、行距偏松，一屏能扫到的信息只有提案的一半（对照 `deliverables/screenshot-feedback-20261102/效果截图/任务详情.jpeg`）。V2 要把「留白换信息」。
- 情绪基调：安静、可信、略有紧迫感（仅逾期/临考用红色触发）。

## 2. Color

### 2.1 令牌

颜色**必须**写进 `app/entry/src/main/resources/base/element/color.json`，页面里用 `$r('app.color.xxx')`。
禁止在 `.ets` 里新增十六进制字面量（现存 1998 处、115 个不同色值，见 `design-contract.md` 基线）。

| 令牌 | 值 | 用途 |
|---|---|---|
| `brand_primary` | `#1151D8` | 主按钮、选中态、链接、关键数字 |
| `brand_pressed` | `#0B3FAE` | 按下/激活 |
| `brand_weak` | `#E8EEFC` | 选中底、标签底、进度槽 |
| `bg_page` | `#F5F7FB` | 页面底色 |
| `bg_surface` | `#FFFFFF` | 卡片、列表、底部栏 |
| `bg_subtle` | `#F0F2F6` | 输入框、次级块、骨架屏 |
| `line` | `#E7EAF0` | 1px 分隔线、卡片描边 |
| `line_strong` | `#D0D5DD` | 输入框/描边按钮边框 |
| `text_1` | `#14181F` | 标题、主文案 |
| `text_2` | `#475467` | 正文、说明 |
| `text_3` | `#667085` | 元信息（时间/来源/题数），对比度 4.97:1 |
| `text_disabled` | `#98A2B3` | 仅占位符、不可用标签；**不得**用于正文 |
| `danger` | `#D92D20` | 逾期、删除、失败 |
| `danger_bg` | `#FEF3F2` | 危险提示底 |
| `warn` | `#B54708` | 需巩固、临期、待处理 |
| `warn_bg` | `#FFFAEB` | 警告底 |
| `success` | `#067647` | 已完成、已核验 |
| `success_bg` | `#ECFDF3` | 成功底 |
| `info_bg` | `#EFF6FF` | 中性提示底 |

### 2.2 使用规则

1. **一屏一强调**：主色只出现在「主动作 + 当前选中 + 一个关键数字」三处，其余用中性色。
2. **状态 = 文字色 + 浅底**，不做四色饱和底块。同一列表里最多出现两种状态色；出现三种时改用文字后缀（如「· 已逾期」）。
3. 红色只给「已逾期 / 删除 / 失败」，**不给**「重要」「高优先级」。优先级用文字 + 中性标签。
4. 深色模式本期不做（提案是纯浅色，做半套反而更花）。令牌化后加 `resources/dark/element/color.json` 即可，不必现在动手。
5. 渐变、彩色阴影、玻璃拟态：**禁用**。

### 2.3 对比度（已核算，白底）

- `text_3 #667085` 4.97 ✅ / `text_2 #475467` 6.0 ✅ / `brand_primary` 6.58 ✅
- `#98A2B3` 2.58 ❌、`#8A93A2` 3.10 ❌ —— 提案里 11–12vp 的灰字大量落在这个区间，落地时统一抬到 `text_3`。
- 白字压 `brand_primary` 6.58 ✅（当前 `#2563EB` 只有 5.17，偏低但合规）。

## 3. Typography

字体：系统默认（HarmonyOS Sans SC），不引入自定义字体。数字统一 `tabular-nums` 效果（ArkUI 用等宽数字或固定宽度容器对齐）。

| 级别 | 字号/字重 | 行高 | 用途 | 每屏上限 |
|---|---|---|---|---|
| `metric` | 32 / Bold | 1.15 | 计时、正确率、总时长 | 1 处 |
| `metric-sm` | 24 / Bold | 1.2 | 卡片内次要数字 | 2 处 |
| `h1` | 22 / Bold | 1.3 | 详情页主标题（「学习报告」「错题本」） | 1 处 |
| `h2` | 17 / Semibold | 1.35 | 区块标题、卡片标题、页头标题 | 每区块 1 处 |
| `h3` | 15 / Medium | 1.45 | 列表行主文案、对话正文 | — |
| `body` | 14 / Regular | 1.55 | 一般正文 | — |
| `small` | 13 / Regular | 1.5 | 次级说明、表单提示 | — |
| `meta` | 12 / Regular | 1.4 | 时间、来源、题数、计数 | — |
| `caption` | 11 / Regular | 1.35 | 角标、tab 文案、行内标签 | — |

规则：

1. **一屏最多 3 个字号**（`metric`/`h2`/`meta` 这类组合足够表达绝大多数页面）。现在代码里有 27 种字号、从 8 到 56，必须收敛。
2. 数字与单位分离：`90` 用 `metric`，`分钟` 用 `caption` 且降为 `text_3`。禁止「90分钟」同字号糊在一起。
3. 正文不用 16–17vp（当前详情页 17vp 是「作品集语气」），改用 14–15。
4. 中文不做 letter-spacing；英文小标签（如 `AI AGENTS`）一律删掉或中文化——提案里已经没有这类眉标。
5. 表格/列表里的数字右对齐，单位左对齐。

## 4. Spacing & Grid

- 基准 4vp；**只允许** `4 / 8 / 12 / 16 / 20 / 24 / 32` 七档。现在代码里 padding 有 18 种取值（4–32），需收敛。
- 页面左右内边距 **16**；卡片内边距 **14**；列表行左右 **16**、上下 **12**（两行内容行高 ≥64，单行 56）。
- 区块间距 **20**；卡片内元素间距 **8 / 12**；图标与文字间距 **10**。
- 圆角只保留四档：`8`（输入框、小标签容器）、`12`（卡片、按钮、列表块）、`16`（底部弹层、大面板）、`999`（胶囊/chip）。当前有 20 种圆角，12/10/8/16/14 五个值就占了 393 次，收敛成本低。
- 触控区 ≥ **44×44**；小图标点击需外扩 hitTest。
- 大屏：正文容器 `.constraintSize({ maxWidth: DeviceLayout.contentMaxWidth() })`（720vp）。现在只有 `Login.ets` 用了，其余 31 个页面在平板上会被拉成一条。

## 5. Layout & Composition

### 5.1 页面骨架（所有二级页统一）

```
[ 状态栏 / 系统安全区 ]
[ Header 56vp : 返回 44×44 · 居中标题 h2 · 右侧文字动作(small, brand) ]
[ 内容区 : bg_page, 左右 16, 上下 12, 可滚动 ]
[ 可选固定底栏 64vp : 1px 上边线 + 主按钮，避开手势条 ]
```

- 标题**居中**或**左对齐二选一**，全 App 只准一种。提案是居中 + 右侧动作，采纳。
- 返回箭头用图标，不用 `‹` 字符；右侧动作最多 1 个，文案 ≤4 字。
- 页面不再出现「← 返回 + 右上角写页面名」这种反置结构（当前 `Account.ets` 就是这样）。

### 5.2 内容编排

1. **首屏必有一张「今天做什么」的主卡**：一行状态（逾期/临期/正常）+ 任务名 + 一条依据（来源课程 · 时长）+ 一个主按钮。其余内容下沉为列表。
2. **列表优于宫格**：超过 4 个入口就用 `ListRow`（图标 20 + 标题 + 副标题 + 右侧箭头/数值），不要 2×3 宫格堆卡片。提案 01C 就是纯列表，扫读效率最高。
3. **详情页自上而下固定四段**：结论 → 依据 → 明细 → 动作。动作永远在最后一段或固定底栏，不夹在中间。
4. **一屏一个主按钮**。次动作做成文字按钮；危险动作红色描边，且必须二次确认。
5. 长内容用 `List` + `ListItem`（复用、滚动性能），不要在 `Scroll` 里直接铺 `ForEach`。

## 6. Components

实现位置：`app/entry/src/main/ets/components/`。全部用 `@Component`（**不要**用带状态参数的 `@Builder`，项目里已踩过「@Builder 按值传参导致选中态不刷新」的坑，见 `ChatMain.ets:468` 注释）。

| 组件 | 规格 | 状态 |
|---|---|---|
| `PageScaffold` | header + body + footer 三段；统一安全区与最大宽度 | — |
| `AppHeader` | 56vp；`title` / `rightText` / `onBack`；标题居中 | 默认、无返回、带右侧动作 |
| `SectionHeader` | 17 Semibold + 右侧 `small` 文字动作 | 默认 |
| `ListRow` | 高 56/64；图标 20；标题 15；副标题 12；右侧 `meta` 或箭头；分隔线内缩 16 | 默认、按下、禁用、选中、危险 |
| `InfoCard` | 白底、12 圆角、1px `line`、内 14；**无阴影** | 默认、强调（左侧 3vp 主色条）、警示 |
| `StatusPill` | 高 22、圆角 999、padding 0/8；11vp | 中性、进行中、已完成、需巩固、逾期 |
| `PrimaryButton` | 高 48、12 圆角、`brand_primary`、15 Medium、宽度撑满 | 默认、按下、加载、禁用 |
| `SecondaryButton` | 高 44、白底、1px `line_strong` | 默认、按下 |
| `SegmentedTabs` | 高 32、`bg_subtle` 槽 + 白色滑块 | 2–4 项 |
| `Metric` | 值（`metric`/`metric-sm`）+ 标签（`caption`/`text_3`） | — |
| `ProgressRow` | 标签 + 细条（4vp）+ 右侧百分比 | 默认、超期 |
| `StateView` | 图标 48 + 标题 17 + 说明 13 + 1 个动作 | `loading` / `empty` / `error` / `waiting` / `offline` / `conflict` **六态一套** |
| `BottomActionBar` | 高 64 + 上边线 + 安全区；1 主 1 次 | — |
| `SheetShell` | `bindSheet`，16 圆角，拖拽条，标题 17 | — |
| `AppTabBar` | 高 56 + 安全区；4 项；图标 22 + 文案 11；仅图标+文案变色，**不加大色块底** | 选中、未选中、角标 |

组件规则：

- 一个组件一个文件，props 全部显式声明；不要靠全局 `appState` 取展示数据。
- 卡片内不再套同色卡片（现在常见「外层白卡 + 内层浅底块 + 行内再一张卡」，层级多于两层就分不清）。
- 图标统一 24×24 线性 SVG，`stroke-width 1.75`，用 `.fillColor()` 染色。
  **禁止** emoji（`🤝` `🌅`）、字符图标（`‹` `◎` `✓` `→`）、以及 PNG 图标与 SVG 混用。
- 状态组件（`StateView`）必须能覆盖提案 14B/14C/14D 里那批「等待中/失败可重试/冲突二选一/权限未开」——这是本次提案最有价值的部分，做成一个组件复用，而不是 15 个一次性页面。

## 7. Motion & Interaction

- 时长：150–200ms；曲线 `ease-out`（ArkUI `Curve.EaseOut`）；页面转场用系统默认，不自定义。
- 层级反馈：卡片按下 `scale 0.99` 或底色变 `bg_subtle`，二选一，全局统一。
- 计时器：数字每秒变化只做透明度呼吸（不做缩放/发光）；暂停时数字降为 `text_3`。
- 加载：优先骨架屏（2–3 行灰条），其次 `LoadingProgress`；**禁止**全屏遮罩转圈。
- 状态切换（提交、保存、完成）必须有即时反馈：按钮进入 loading → 行内成功提示（`success_bg` 一条，3s 自动消失）→ 列表就地更新。不要弹 Toast 承担主反馈。
- 不引入：视差滚动、粒子、渐变呼吸、长按彩蛋。

## 8. Voice & Brand

- 品牌锚点保留一句话：**「今天，先完成一件事。」**（当前 `ChatMain` 的 hero 文案，提案压缩掉了，建议保留为一行 `h2` + 主卡，不再用 26vp 双行大字）。
- 文案三原则：
  1. 动词开头、≤12 字：「开始专注」「确认并写入」「查看原文依据」。
  2. 结论必须带口径：「近期正确率 67%（近 7 天 · 12 题）」，不许只写 67%。
  3. 不确定就说不确定：「待首次测评」「样本不足，暂不计算」，不编数。
- 术语表（全 App 统一，禁止同义混用）：
  `知识点` / `课程` / `掌握度` / `有效题` / `原文依据` / `学习目标` / `阶段复盘` / `学习搭子` / `专注` / `决策记录（Agent Trace）`。
- **「问知学」只保留一个全局入口**（现有悬浮球 + 底部弹层），删掉每个页面右上角的文字按钮。提案里十几个页面都画了「问知学」，实现会变成十几份重复逻辑，且和悬浮球语义冲突。
- **禁止**把「演示数据 / 示例状态 / 未验证」这类标注放进正式 UI。演示模式做成全局开关，开启时顶部一条细提示条即可。

## 9. Anti-patterns

以下都是**当前代码或提案里真实存在**的，逐条禁止：

1. 26vp 双行问候 hero + 10vp 英文眉标 + 分隔线（现 `ChatMain.WelcomeBlock`，第 905–931 行）。
2. 首屏出现 3 个并列 CTA（提案 01A：开始任务 / 查看全部待办 / 输入框发送）。
3. 同一列表里 4 种饱和状态底（提案 05B/06A）。
4. 393vp 宽度放 4 列表格（提案 05D 课程/日期/优先级/操作）。
5. 一屏 6 个区块 + 2 层嵌套卡片（提案 06C）。
6. Emoji 当图标、字符当图标、PNG 与 SVG 混用。
7. 每个页面重复实现页头（当前 17 个页面里 15 个手写返回栏，只有 2 个用 `PageHeader`）。
8. 每个页面重复实现底部 Tab（`ChatMain.ets` 与 `Index.ets` 各一套）。
9. 把开发调试页（接口环境、后端地址、Trace 重置）放进主流程；一律收到「关于 → 连点版本号」后。
10. 展示「暂不可用」但不给原因与替代路径（提案 11A 华为账号登录）。
11. 新增十六进制颜色字面量、魔法间距、20 种圆角、27 种字号。
12. 12vp 以下正文、`#98A2B3` 当正文色。
13. 卡片阴影 + 渐变 + 彩色描边三件套。
14. 用 Toast 承担唯一反馈。
15. 为「未来可能的需求」提前抽象组件（先有 3 处相同写法再抽）。
