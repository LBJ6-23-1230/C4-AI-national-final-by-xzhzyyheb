# 设计决策记录（design-contract.md）

## 1. 任务

- **目标产物**：知学 Mate（HarmonyOS 元服务/应用）的 UI V2 改版 —— 把现有 32 个 ArkTS 页面改成 `参考图/` 提案的视觉与信息结构。
- **受众**：① 全国决赛现场评委（3–5 分钟内扫读 10–15 屏）；② 真实使用的大学生（每天 3–5 次，单手竖屏）。
- **上下文**：现有功能与接口已相当完整（`contracts/openapi.json` 有 81 条路径），本次是**视觉与信息架构升级**，不是功能开发。
- **约束**：本轮只评审、不改代码；后续实现须保持路由、状态机与接口调用不变。

## 3. Keep / Change / Do not copy

参考对象即 V2 提案本身。**借的是可复用的观感与结构，不是逐屏施工图。**

### Keep（保留）

- **信息密度**：小字号、紧凑行高、列表优先。这是 V2 相对现状最大的收益。
- **列表行的语法**：图标 20 + 主文案 15 + 副文案 12 + 右侧数值/箭头，行高 56–64。
- **页头语法**：56vp、居中标题、右侧一个文字动作、返回用图标。
- **语义色的使用逻辑**：蓝=进行中/主色，红=逾期，橙=需巩固/临期，绿=已完成；且**只用文字+浅底**。
- **状态完备性**（14B/14C/14D）：等待中、失败可重试、冲突二选一、权限未开、恢复上次专注、时间不足。这些是「工程完整性」得分点，也是当前 App 最缺的。
- **「原文依据 / 逐题解析 / AgentTrace」这类可核验证据块**：与项目「可核验」叙事同构，是差异化，不要为了简洁砍掉。
- **固定底栏 + 单一主按钮**的收尾方式。

### Change（改造后采纳）

| 提案做法 | 改成 | 原因 |
|---|---|---|
| 01A 首屏三个 CTA（开始任务/查看全部待办/输入框） | 一个主卡主按钮 + 输入框；「查看全部」降为卡片右上文字动作 | 首屏主次冲突 |
| 01A 丢掉「今天，先完成一件事」 | 保留为一行 `h2` + 主卡，不用 26vp 双行 hero | 品牌锚点不能全丢 |
| 01B 五张智能体卡各带 2 个次级链接 | 每卡 1 句能力 + 1 个主动作；次级入口收进详情 | 重复信息、点击目标过多 |
| 每页右上「问知学」 | 只保留全局悬浮球 + 弹层一个入口 | 十几份重复实现，且与悬浮球语义冲突 |
| 05D 课程/日期/优先级/操作 4 列表格 | 卡片行 + 展开编辑（点行进入编辑态） | 393vp 放不下 4 列，真机必崩 |
| 06C「预算 / 候选 / 未安排 / 拆分 / 合计」一屏 | 拆成「预算与候选」→「拆分与确认」两步 | 一屏 6 块，滚动 2 屏以上 |
| 10A 八个指标平铺 | 3 个核心指标（时长/正确率/待处理）+ 1 个行动 | 无主次，等于没重点 |
| 12B 提醒设置 与 14A 提醒状态与权限 两屏 | 合并：设置页顶部加一条状态条（权限/服务/设备） | 同一功能两处，用户与评委都分不清 |
| 13B 接口环境页 | 保留功能，但只在「关于 → 连点版本号」后可达；不参与视觉改版 | 调试页不是产品页 |
| 11A 三个并列入口（演示身份/离线模式/华为账号-暂不可用） | 华为账号为主入口；演示与离线收进「更多」；「暂不可用」不给无原因文案 | 评委会点 |
| 04D 顶部左右箭头 + 底部「同类练习/继续下一题」两套翻页 | 只保留一套（顶部题号切换） | 交互重复 |
| 03D 底部固定「保存匹配」但页面是列表 | 改为选中即保存（行内勾选）+ 底部「完成」 | 保存对象不明 |
| 全局 4 色状态底 | 最多 2 种状态色 + 文字后缀 | 色彩噪音 |
| 60 屏全量 | 按演示路径做 P0/P1（见 `提案评审与页面清单.md`） | 工作量与收益不匹配 |

### Do not copy（禁止照搬）

- 提案里的具体演示数据与人物（林知远 / 苏念 / xzh2 / 67% / 55 分），以及「展示数据」水印。
- 14B 里明确标注「示例状态」的并行展示方式 —— 正式页面一次只呈现一种状态。
- 05D 的 4 列表格版式、06C 的六块同屏密度。
- 11A「华为账号登录 · 暂不可用」这种无解释的灰色入口。
- 13B 开发调试页的视觉（后端地址输入框、检测日志）。
- 09D 把失败提示条放在消息流中间的做法（应贴在输入框上方）。
- 任何知名产品的品牌色/图标/文案；只借结构与节奏。

## 4. 设计立场（一段话）

**把知学 Mate 从「展示型作品集界面」改造成「可核验的学习工作台」**：主色收敛为一种深蓝 `#1151D8`，底色退到 `#F5F7FB`，卡片只靠 1px 边框分层、不用阴影；字号从 27 种收敛到 9 级、圆角从 20 种收敛到 4 档；页面结构统一为「56vp 页头 + 列表/卡片内容 + 可选固定底栏」；信息组织从宫格卡片改为列表行；所有 AI 结论旁边必须出现来源或口径；边界状态用一套 `StateView` 组件覆盖，而不是 15 个一次性页面。视觉上更接近系统工具，态度上更克制，但保留「今天先完成一件事」这一句品牌主张和一个全局「问知学」入口。

## 5. 风险与未知

### 5.1 系统性风险

| # | 风险 | 影响 | 处置 |
|---|---|---|---|
| R1 | 按 60 屏逐屏施工 | 工作量为 20–27 人日，赛前做不完或做一半更难看 | 只做 P0/P1（约 20–24 屏），P2 状态页用 `StateView` 兜底 |
| R2 | 页面重排时顺手改逻辑 | 32 页里 12 页超 500 行且状态耦合重（`ChatMain` 1341 行、`KnowledgeBase` 1265 行） | 只动 UI 层；每页改完必须能编译 + 跑通原路径；禁止顺手重构状态 |
| R3 | 全局替换 `#2563EB → #1151D8` | 会误伤语义红/绿、渐变阴影、Canvas 绘制色 | 按语义映射替换，逐页目检；Canvas/图表单独处理 |
| R4 | 图标资源缺失 | 只剩 emoji 和字符图标，观感立刻掉档 | 先定 24×24 SVG 图标集（约 30 个），`fillColor` 染色；没有的先用系统 `SymbolGlyph` |
| R5 | 部分状态无接口支撑（等待、冲突） | 只能写死文案，评委会追问 | 能用现有状态机推导的就做，不能的降级为「加载/空/错误」三态 |
| R6 | 平板/2in1 仍被拉伸 | 「全场景」叙事被戳破 | 所有页面套 `DeviceLayout.contentMaxWidth()`；演示只用手机 |
| R7 | 死线未知 | 计划无法排 | 先按「1 周 / 2 周 / 3 周」三档排（见 handoff） |
| R8 | 深色模式 | 提案没有，做了要双倍走查 | 明确不做；令牌化后留给以后 |

### 5.2 逐页问题（必须在开工前定稿）

详见 `提案评审与页面清单.md` 第 2 节，共 18 条，其中**阻塞级 5 条**：

1. **对话页到底是首页还是聊天页？** 01A 与 02A 是两套信息架构，必须先定一个首屏形态。
2. **「问知学」是全局能力还是页面动作？** 决定要写 1 套还是 12 套。
3. **05D 识别校正用什么版式？** 表格在 393vp 不可行，需改卡片行。
4. **06C 是否拆两步？** 不拆则必须砍掉「拆分步骤可编辑」。
5. **13B 接口环境页是否进入正式导航？** 建议否。

### 5.3 未知（需要产品/设计确认）

- 决赛日期与可投入人力。
- 是否已有图标资产（Figma/SVG）或只能代码里画。
- 华为账号登录当前是否可演示（提案写「暂不可用」）。
- 演示机分辨率与是否用平板投屏。
- 是否接受删除「学习页宫格入口」改为纯列表（会影响现有快捷入口的发现性）。
