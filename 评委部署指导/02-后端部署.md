# 后端部署与验收

> 香港评审实例已配置公网入口。评委联机请见 [云端评审快速开始](00-云端评审快速开始.md)，团队运维请见 [香港评审实例](../server/zhixue-agent-server/deploy/香港评审实例.md)。

现场演示建议使用 Windows、Python 3.12 和本机 SQLite。模拟器和电脑可在同一台机器上运行。真机和模拟器要演示跨设备同步时，连接同一个后端。Linux 长期部署见本文末尾。

## 一、Windows 从零启动

1. 完整解压提交包，在资源管理器中找到含有 `start-backend.ps1`、`app` 和 `server` 的目录。在该目录的空白处右键，选择「在终端中打开」。终端使用 PowerShell。
2. 检查 Python。第一行应显示 Python 3.12.x。缺少时安装 Python 3.12（Windows x64），勾选 Python Launcher，然后重新打开终端。

   ```powershell
   py -3.12 --version
   Test-Path .\start-backend.ps1
   ```

3. 在项目根目录创建虚拟环境，并用随包的 Windows x64 安装包补齐依赖。`pip check` 应显示 `No broken requirements found.`。此操作只需在首次部署或依赖更新后执行。

   ```powershell
   $backend = '.\server\zhixue-agent-server'
   $python = Join-Path $backend '.venv\Scripts\python.exe'
   if (-not (Test-Path -LiteralPath $python)) {
       py -3.12 -m venv (Join-Path $backend '.venv')
       if ($LASTEXITCODE -ne 0) { throw '创建 Python 虚拟环境失败。' }
   }
   & $python -m pip --disable-pip-version-check install --no-index --find-links '.\offline-wheels\windows-py312' -r (Join-Path $backend 'requirements.txt')
   if ($LASTEXITCODE -ne 0) { throw '安装依赖失败。请检查 Python 版本、架构和解压目录。' }
   & $python -m pip check
   ```

   需要从软件包索引安装时，用 `& $python -m pip install --timeout 120 --retries 8 -r (Join-Path $backend 'requirements.txt')`。连接超时后可沿用同一 `.venv` 重试。其他平台使用对应系统的 Python 3.12 环境，或使用本页末尾的 Compose 部署。

4. 创建本地配置。已有 `.env` 时先检查里面的配置，确认它指向本次演示的新库。下面的命令只在文件不存在时创建它。

   ```powershell
   $config = '.\server\zhixue-agent-server\.env'
   if (-not (Test-Path -LiteralPath $config)) {
       Copy-Item '.\server\zhixue-agent-server\.env.example' $config
       @'

   APP_ENV=development
   ZHIXUE_ENV=development
   ZHIXUE_DB=sqlite
   DEMO_ENABLED=true
   ZHIXUE_ENABLE_DEV_TOOLS=0
   FILE_STORAGE=local
   '@ | Add-Content -LiteralPath $config -Encoding utf8
   }
   ```

5. 在同一个 PowerShell 窗口启动。看到 `Running on ...:5000` 后保留该窗口。关闭服务时回到此窗口按 **Ctrl+C**。

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\start-backend.ps1 -Port 5000
   ```

   Windows 允许查询监听端口和进程命令行（CIM）时，可在首次安装依赖成功后使用 `powershell -NoProfile -ExecutionPolicy Bypass -File .\start-all.ps1 -NoWorker -NoDeviceBridge`。加上 `-Status` 可查询，加上 `-Stop` 可停止。遇到 CIM 权限不足时使用上述前台启动。SQLite 模式使用 API 进程处理本地任务。

## 二、先用电脑确认 API，再连 App

在第二个 PowerShell 窗口执行以下命令。前两行分别应返回 `status: ok`、`status: ready`。第三行查看模型配置与验证状态。

```powershell
Invoke-RestMethod 'http://127.0.0.1:5000/health'
Invoke-RestMethod 'http://127.0.0.1:5000/ready'
Invoke-RestMethod 'http://127.0.0.1:5000/api/agent/health'
```

在 App 中打开「接口环境」，填写与设备连接方式对应的地址，保存后再进入登录或体验。只填服务基地址，后面的 API 路径由 App 添加。

| 设备 | 填写示例 | 核对方法 |
| --- | --- | --- |
| 本机 DevEco Studio 模拟器 | `http://10.0.2.2:5000` | 先确认电脑的 `127.0.0.1:5000/ready` 正常，再做 App 内连接测试 |
| 与电脑同一局域网的真机 | `http://192.168.1.20:5000` | 示例 IP 换成电脑 `ipconfig` 中当前连接网卡的 IPv4。先在真机浏览器打开该地址加 `/ready` |
| USB 调试、HTTPS | 见本套真机连接说明 | 使用同一套 USB 转发、证书和 App 地址配置 |
| 已部署的云后端 | `https://api.example.com` | 域名换成自己的域名，并在设备浏览器确认 `/ready` |

本地演示可从 App 的注册入口创建一个本地账号，填写测试手机号、昵称和密码。跨设备登录请在两台设备上填写同一手机号和密码，两台设备连接同一后端。在受控演示环境使用自选测试数据。当前版本未接入真实短信发送，现场请走手机号和密码。华为账号登录依赖同一个 AGC 应用的客户端配置和设备信任的 HTTPS 后端。

### 可选的模型功能

基础注册、登录、课表与 DDL 导入、学习记录和规则演示可先验收。需要验证模型聊天、知识点出题、图片识题或向量检索时，请在本机后端 `.env` 设置自己的 `DASHSCOPE_API_KEY`，根据账号有权使用的模型设置 `LLM_MODEL`、`LLM_DECISION_MODEL`、`LLM_VL_MODEL` 和 `EMBED_MODEL`，重启后端，再用下方命令验证。脚本会实际请求供应商，可能产生调用费用。

```powershell
.\server\zhixue-agent-server\.venv\Scripts\python.exe .\tools\check_llm_ready.py
```

`/api/agent/health` 的 `configured` 只表示读到了配置。未配置模型时，聊天仍可展示规则分支，出题与视觉识别等依赖模型的操作会提示不可用。需要现场使用的模型应各自跑一遍。密钥留在后端，App 连接地址只填写 API 主机。

## 三、在 Windows 使用已有 PostgreSQL 和独立 Worker

这一方式适合使用评审方自己的演示库，验收独立进程处理知识库等后台任务。先完成第一节的依赖安装。使用新库时，按[数据库与备份](03-数据库与备份.md)创建专用数据库、迁移并授权。API 和 Worker 启动时都要求库结构版本为 `20261031_01`。

1. 停止同端口上此前启动的 SQLite 服务。用文本编辑器打开 `server/zhixue-agent-server/.env`，替换原有同名配置。把示例中的账号、密码、主机、端口、库名换成评审库的实际值。连接账号须具有 API 和 Worker 所需的数据表权限。部署方要求 TLS 时，加上对应证书及 `sslmode` 参数。

   ```dotenv
   APP_ENV=development
   ZHIXUE_DB=postgresql
   DATABASE_URL=postgresql+psycopg://REVIEW_USER:REVIEW_PASSWORD@DB_HOST:5432/REVIEW_DB
   DEMO_ENABLED=true
   ZHIXUE_ENABLE_DEV_TOOLS=0
   FILE_STORAGE=local
   ```

2. 在项目根目录执行以下命令。状态应显示 `API 运行中 /ready 200` 和 `Worker 运行中`。上传 TXT 样例后，在知识库查看处理状态。若有模型相关报错，按第二节检查模型配置。

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\start-all.ps1 -NoDeviceBridge
   powershell -NoProfile -ExecutionPolicy Bypass -File .\start-all.ps1 -Status -NoDeviceBridge
   Invoke-RestMethod 'http://127.0.0.1:5000/ready'
   ```

3. 脚本在 `logs/` 记录 `api-5000.err.log` 和 `worker.err.log`。停止时用 `powershell -NoProfile -ExecutionPolicy Bypass -File .\start-all.ps1 -Stop -NoDeviceBridge`。需要独立提醒 Worker 时，启动命令另加 `-WithReminders`，真机通知条件见[提醒 Worker 说明](../server/zhixue-agent-server/deploy/reminder-worker.md)。

如果系统限制 CIM 查询，开两个 PowerShell 窗口，分别进入 `server/zhixue-agent-server`。第一个执行 `& .\.venv\Scripts\python.exe run.py --port 5000`，第二个执行 `& .\.venv\Scripts\python.exe worker.py`。用 **Ctrl+C** 停止对应进程。

## 四、常见故障

| 现象 | 处理 |
| --- | --- |
| 脚本提示找不到 `.venv` 或依赖缺失 | 回到项目根目录运行第一节的离线依赖安装，确认 Python 3.12 x64 和 `offline-wheels/windows-py312/` 完整 |
| pip 安装报 `[Errno 2]`，路径指向 `.venv` 内的依赖文件 | 把 ZIP 重新解压到英文短路径（如 `C:\C4`），在新目录创建 `.venv` 后再安装 |
| 5000 已占用 | 用 `netstat -ano -p tcp` 查看本机端口和 PID。选择其他端口时，启动命令、两个探针和 App 地址一起改 |
| `/health` 正常、`/ready` 返回 503 | 按[数据库检查](03-数据库与备份.md)查看使用的库文件、进程对目录的权限和 PostgreSQL 迁移头 |
| `/ready` 无法连接且 API 日志报 PostgreSQL 超时 | API 可能在监听前退出。检查评审电脑到数据库主机和端口的连通性，检查数据库服务和监听状态，连接恢复后再启动 |
| 电脑可访问、真机访问失败 | 确认两端网络可以互访、App 使用电脑 IPv4、Windows 允许受信专用网络访问所用端口。校园访客网络可能隔离设备，可改用 USB 或同一台电脑的模拟器 |
| 登录提示账号不存在 | 核对 App 连接的后端与启动日志中的数据库路径。新解压的部署使用新库，在该库中注册一次即可 |
| `worker.py` 启动后退出 | 本地 SQLite 使用 `start-backend.ps1`，或给 `start-all.ps1` 加 `-NoWorker`。云端 Worker 则检查 PostgreSQL、授权和容器日志 |
| `worker.err.log` 出现 `worker_db_unavailable` | 持续运行的知识库 Worker 正等待 PostgreSQL 恢复并会自动重试。日志持续出现时检查数据库服务和网络 |
| 配了 Key 仍提示模型不可用 | 重启后先查模型验证结果，再查模型名称、区域、API 配额、出网与供应商错误码 |

## 五、Linux HTTPS 部署（可选）

需要长期开放服务或用可信 HTTPS 做 Account Kit 验收时，准备 Linux 主机、Docker Compose v2、独立 PostgreSQL 实例或 RDS、可用的域名证书和私有 OBS/S3 桶。API 与数据库走私网，公网开放 443，80 用于 HTTPS 跳转。此方案使用部署方自己的数据库和存储凭据。

1. 在 `server/zhixue-agent-server` 下执行，生成配置文件和挂载目录。

   ```sh
   umask 077
   cp -n .env.production.example .env.production
   cp -n .env.worker.example .env.worker
   cp -n .env.migration.example .env.migration
   mkdir -p deploy/certs deploy/runtime-secrets
   docker build -t zhixue:judge-20261111 .
   ```

2. 将域名证书链与对应私钥分别放在 `deploy/certs/fullchain.pem`、`deploy/certs/privkey.pem`。将数据库 CA 放到 `deploy/runtime-secrets/rds-ca.pem`，让容器 UID 10001 能读取 CA。将 `.env.production` 中的 `APP_IMAGE` 设为 `zhixue:judge-20261111`，填好对象存储连接和 API 的数据库 URL。
3. 按[数据库与备份](03-数据库与备份.md)创建迁移角色、API 角色和 Worker 角色，填好 `.env.migration`、`.env.worker`。先执行迁移，再执行授权。迁移和授权通过后启动服务。

   ```sh
   docker compose --env-file .env.production config --quiet
   docker compose --env-file .env.production up -d --wait api worker gateway
   docker compose --env-file .env.production ps
   docker compose --env-file .env.production logs --tail=50 api worker gateway
   curl --fail https://api.example.com/health
   curl --fail https://api.example.com/ready
   ```

4. 将示例域名换成真实域名后，在 App 填写相同的 HTTPS 基地址。启用系统提醒时，另按[提醒 Worker 说明](../server/zhixue-agent-server/deploy/reminder-worker.md)配置。使用镜像仓库发布、迁移已有数据及运维告警见[云端部署与迁移手册](../server/zhixue-agent-server/deploy/README.md)。
