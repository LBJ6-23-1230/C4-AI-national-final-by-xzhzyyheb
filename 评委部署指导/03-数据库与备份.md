# 数据库部署、检查和备份

Windows 现场演示使用独立 SQLite 文件，一次启动即可自动建库。只有需要长期共享数据库、独立后台任务或正式 HTTPS 服务时，才需要下文的 PostgreSQL。

## 一、SQLite 首次启动和检查

1. 按[后端部署](02-后端部署.md)创建 `.env`，确认有 `ZHIXUE_DB=sqlite`，再启动后端。应用会在 `server/zhixue-agent-server/data` 新建 `repository.sqlite`，以及临时 WAL 文件。第一次启动时账号数量为空是正常现象。
2. 在提交包根目录另开一个 PowerShell 窗口。先查看 HTTP 就绪，再核对实际库文件和记录数量。

   ```powershell
   Invoke-RestMethod 'http://127.0.0.1:5000/ready'
   Get-Item '.\server\zhixue-agent-server\data\repository.sqlite'
   .\server\zhixue-agent-server\.venv\Scripts\python.exe .\tools\check_database.py --verbose
   ```

   应看到 `ready`、实际库文件路径、`SQLite 可读` 和 `GET /ready -> 200 ready`。可再从 App 注册一个测试账号，导入样例课程表与 DDL，重启同一目录的后端，然后重新登录检查学习数据仍在。
3. 独立查库文件完整性时，可执行以下命令。应输出 `ok`。该命令以只读方式打开现有文件，路径不对时会报错。

   ```powershell
   .\server\zhixue-agent-server\.venv\Scripts\python.exe -c "from pathlib import Path; import sqlite3; p=Path(r'server/zhixue-agent-server/data/repository.sqlite').resolve(); c=sqlite3.connect(p.as_uri()+'?mode=ro',uri=True); print(c.execute('PRAGMA quick_check').fetchone()[0]); c.close()"
   ```

如果原来已用 JSON 并且要保留账号和记录，先停服并备份，确认源文件与目标路径，在提交包根目录执行 `python tools/migrate_repository.py --dry-run`，核对后执行 `python tools/migrate_repository.py --verify`，再切换到 SQLite。已有 SQLite 目标时先核对它的内容，迁移工具默认保护已有数据。JSON 源和本地聊天历史均应随备份保留。

## 二、SQLite 备份和恢复

本地演示数据由数据库、聊天历史和可能存在的上传原件组成。备份前关掉 App 正在进行的写入，按 **Ctrl+C** 停止前台后端。使用后台模式时执行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\start-all.ps1 -Stop -NoWorker -NoDeviceBridge`。确认该演示库的所有进程已退出后，在提交包根目录执行：

```powershell
$server = '.\server\zhixue-agent-server'
$backup = Join-Path $env:LOCALAPPDATA ('ZhixueMate\Backups\' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path "$backup\data", "$backup\chat" | Out-Null
Copy-Item -LiteralPath "$server\data\repository.sqlite" -Destination "$backup\data\"
if (Test-Path -LiteralPath "$server\data\repository.sqlite-wal") {
    Copy-Item -LiteralPath "$server\data\repository.sqlite-wal" -Destination "$backup\data\"
}
if (Test-Path -LiteralPath "$server\chat\history.json") {
    Copy-Item -LiteralPath "$server\chat\history.json" -Destination "$backup\chat\"
}
if (Test-Path -LiteralPath "$server\data\files") {
    Copy-Item -LiteralPath "$server\data\files" -Destination "$backup\data\" -Recurse
}
Write-Host "备份目录 $backup"
```

以上命令使用默认存储路径。自定义了 `ZHIXUE_REPOSITORY`、`ZHIXUE_DB=sqlite:<path>`、`ZHIXUE_CHAT_DIR` 或 `FILE_STORAGE_DIR` 时，按实际目录备份同一时点的数据。备份内含账号和业务数据，请放在仅部署者可访问的目录。

恢复时先在另一个目录完整解压提交包，保留原工作目录。确认新目录尚未启动，在其中将备份的 `data` 内文件复制到 `server/zhixue-agent-server/data`，将备份的 `history.json`（如有）复制到 `server/zhixue-agent-server/chat`，然后按[后端部署](02-后端部署.md)配置 SQLite 和启动。先检查 `/ready` 与 `PRAGMA quick_check`，再用原测试账号核对课程、DDL、聊天记录和资料。原服务还在运行时使用另一个端口，并在 App 中切到恢复实例的地址。

## 三、PostgreSQL 首次部署（可选）

### 1. 创建独立数据库与角色

建议使用学校或主办方自己管理的 PostgreSQL 17/RDS 实例，单独建一个演示数据库。数据库仅允许部署主机通过受控网络连接。以下命令只用于新的专用数据库。数据库管理员在 `psql` 中执行，`\password` 会交互询问密码。

```sql
CREATE ROLE zhixue_migration_login LOGIN;
CREATE ROLE zhixue_api_login LOGIN;
CREATE ROLE zhixue_worker_login LOGIN;
\password zhixue_migration_login
\password zhixue_api_login
\password zhixue_worker_login
CREATE DATABASE zhixue OWNER zhixue_migration_login;
\connect zhixue
REVOKE CONNECT ON DATABASE zhixue FROM PUBLIC;
GRANT CONNECT ON DATABASE zhixue TO zhixue_migration_login, zhixue_api_login, zhixue_worker_login;
```

### 2. 填写连接并执行迁移

分别编辑 `.env.production` 中的 `DATABASE_URL`（API）、`.env.worker` 中的 `DATABASE_URL`（Worker）和 `.env.migration` 中的 `MIGRATION_DATABASE_URL`（迁移角色）。使用各自的登录名和密码，保留如下连接格式。用户名或密码含有 `@`、`:`、`#` 等字符时，按 URL 规则对相应部分编码。

```text
postgresql+psycopg://用户名:密码@实际RDS主机名:5432/zhixue?sslmode=verify-full&sslrootcert=/run/secrets/rds-ca.pem
```

数据库证书应覆盖所用主机名。按[后端部署](02-后端部署.md)挂载数据库 CA 后，在 `server/zhixue-agent-server` 下执行迁移。

```sh
docker compose --env-file .env.production --profile tools run --rm migrate
```

迁移成功后，用具有建角色和授权权限的管理员连接 **zhixue** 数据库。运行 `deploy/roles.sql`。该文件会创建 3 个集群级角色，首次执行一次。已有同名角色时先由管理员核对，再应用需要的授权语句。安装了多个环境的管理员应分别核对同一实例上的角色成员关系。

```sql
\i deploy/roles.sql
GRANT zhixue_api TO zhixue_api_login;
GRANT zhixue_worker TO zhixue_worker_login;
SELECT version_num FROM alembic_version;
```

当前预期迁移头为 `20261031_01`。随后启动 Compose 并通过 HTTPS 访问 `/ready`。连接失败时检查数据库私网地址、端口、安全组、角色密码、CA 文件与容器读取权限。迁移头不一致时用迁移角色补齐结构。历史库有重复规范化手机号时，先备份并用 `tools/audit_phone_accounts.py` 生成受控审计，再依[迁移手册](../server/zhixue-agent-server/deploy/README.md)处理归属。

### 3. 备份与恢复

开启 RDS 自动备份，并安排一次到新库的恢复演练。逻辑备份时，为备份角色配置受保护的 libpq service/password 文件，给备份角色连接权限和必要的只读授权。后端目录内可执行：

```sh
export PGSERVICE=zhixue-backup
export BACKUP_DIR=/path/to/private-backups
sh deploy/backup.sh
```

脚本会生成 `.dump`、结构清单与 SHA-256。恢复时先另建空库并把 libpq 服务 `zhixue-recovery` 配到该库的迁移角色。将下方示例路径换成要恢复的备份。

```sh
pg_restore --exit-on-error --no-owner --dbname='service=zhixue-recovery' /path/to/zhixue-backup.dump
```

核对迁移版本与业务计数，重新应用适合该环境的权限，再用测试 API 和 Worker 验收。原始上传在独立的私有 OBS/S3 桶中，需要对桶单独做备份或版本保留。详细的角色、恢复、迁移及监控流程见[云端部署与迁移手册](../server/zhixue-agent-server/deploy/README.md)。
