# 知学 Mate 上架清单（2026-11-04）

> 依据：华为官方《应用资质审核要求》(80301)、《计算机软件著作权证书》(50111-02)、《APP核准（APP备案）指引》(50130)，均为 2026-11 现行版本。
> 项目侧状态：后端 922 项测试通过、四端模拟器可安装运行、大模型与数据库实测可用（见 `evidence/emulator-check-20261104`、`evidence/database-check-20261104.log`）。

---

## 0. 一句话结论

**项目本身已经具备上架条件；卡点上架的是三件事：① App 备案（强制）；② 生成式 AI 类资质（因为产品是 AI 助手）；③ 公网 HTTPS 后端 + release 签名包。软著不是必须的。**

---

## 1. 软著到底是不是必须？

| 问题 | 结论 |
|---|---|
| 普通应用必须吗 | **不必须**。官方原文：“APP软件著作权证书为‘非必选资质’，但建议您申请……以保护您的知识产权。” |
| 游戏必须吗 | **必须**（游戏类目要求软著/电子版权/软著认证三选一，另需版号） |
| 知学 Mate 属于 | 普通应用（非游戏）→ **不是硬门槛**，时间紧可以不上传 |
| 但要注意 | ① 商店“版权信息”页仍建议上传，审核可能索要；② 软著上的软件名称必须与应用名 **“知学 Mate”** 一致；③ 著作权人必须与开发者主体一致，否则要《应用版权授权书》 |
| 更快的替代 | 《APP电子版权认证证书》办理周期比软著短、费用低，华为明确认可 |

## 2. 硬门槛（缺一项就无法上架）

- [ ] **App 备案（工信部核准）** —— 强制。未备案不得从事 App 互联网信息服务，应用市场会校验，未通过会影响搜索展示甚至在安装环节提示“未备案”。
  - 路径：服务器接入商（华为云/阿里云/腾讯云等）→ ICP 备案 → 新增 App → **平台勾选“鸿蒙”** → 填包名 `com.zhixue.mate`、应用名“知学 Mate”。
  - 前提：**大陆服务器 + 已备案域名**（与第 3 项同一件事）。
- [ ] **生成式 AI 类资质** —— 因为应用提供大模型对话/识图/出题，80301 把“深度合成或生成式人工智能服务”单列一类，要求：
  - [ ] AI 生成合成内容**显式标识**（应用内截图）或《人工智能生成合成内容标识说明函》
  - [ ] **互联网信息服务算法备案**（生成合成类）查询截图 —— 自有或合作方备案 + 合作协议
  - [ ] **《安全评估报告》**
  - [ ] 安全评估报告在**全国互联网安全服务管理平台**的提交结果截图（“通过/审核通过”）
- [ ] **公网 HTTPS 后端** —— 审核会实机验证。当前源码是 `http://10.0.2.2:5000`，数据库是内网 `10.83.13.161`，**上架包必须改成公网域名**（`tools/prepare_app_environment.py --environment production --api-url https://api.xxx.cn`）。
- [ ] **release 签名包** —— 现有 `hap/知学Mate-signed.hap` 经验签为 `profile type is: debug`，商店只收 release 包。需用 `zhixue-release-profileRelease.p7b` + `zhixue-release.cer` 重新构建，验签必须显示 `release`。
- [ ] **隐私政策公网页面** —— HTTPS 可访问，写清主体、联系方式、收集的数据种类、第三方 SDK（通义/DashScope、OBS）、保存期限、删除方式。
- [ ] **个人信息收集清单 + 第三方共享清单** —— AGC 隐私标签/审核会核对。
- [ ] **权限使用说明** —— 麦克风、分布式数据同步（“发现和连接附近设备”）、网络状态，逐条写用途。
- [x] **账号注销** —— 后端 `DELETE /api/v1/auth/account` 已实现。
- [ ] **审核测试账号** —— `demo-user` / `19338435921` 可跳过登录；审核期间后端必须在线。

## 3. 条件性资质（取决于功能边界）

| 功能 | 触发资质 | 当前判断 |
|---|---|---|
| 用户之间聊天/社区/通讯 | 《安全评估报告》+ 平台提交截图；涉及互联网信息服务还需《增值电信业务经营许可证》 | 学习搭子是**匹配推荐 + AI 解读**，未见用户间 IM；若后续加私信则触发 |
| 义务教育学科培训 | 省级教育行政部门备案 | 建议对外定位 **“学习工具/效率”**，不要写“学科辅导/培训” |
| 直播/短视频/新闻/出版 | 对应许可证 | 不涉及 |
| 个人开发者 | 《个人开发者承诺函》 | 若是个人主体，提交时一并上传 |
| 深度合成拟人化互动 | 省级网信部门专项要求 | 当前 AI 为学习助手，非拟人陪聊；描写时避开“虚拟人/陪聊” |

## 6. 提交流程（顺序）

1. 打 release 包并验签 → 2. 「软件包管理」上传 → 3. 填版权/备案信息 → 4. 填介绍与素材 → 5. 「准备提交」选版本 → 6. 填审核信息（测试账号、功能说明、AI 说明）→ 7. 提交审核 → 8. 审核 1–3 个工作日。

---

## 7. 时间估算

| 场景 | 时间 |
|---|---|
| 只差填表（备案、域名、签名、素材全齐） | 提交半天 + 审核 1–3 工作日，可能驳回 1–2 轮 → **3–7 天** |
| App 备案从零开始 | **1–2 周**（域名实名 + 服务器 + 管局审核） |
| 走生成式 AI 类目（算法备案 + 安全评估） | **1–3 个月**，且算法备案主体通常要求企业/组织，个人开发者一般无法完成 |
| 软著（若决定办） | 普通 30–60 天，加急 3–7 天；电子版权认证更快 |

---

## 8. 最大风险（按严重度）

1. **AI 类目资质**：产品核心就是大模型，审核大概率按“生成式人工智能服务”要求材料；个人主体很难完成算法备案，需要考虑学校/企业主体，或使用模型方备案 + 合作协议（需正式协议）。
2. **公网后端 + 备案**：没有大陆已备案域名，App 备案和上架都走不通；这是纯外部流程，越早启动越好。
3. **release 签名**：技术上一小时能解决，但需要签名口令（向队长索取），且 `build-profile.json5` 当前 `signingConfigs` 为空。
4. **隐私政策与权限说明**：AI 应用最常被驳回的点，务必写全数据流（问题、图片、成绩、聊天记录都出境到模型服务）。
