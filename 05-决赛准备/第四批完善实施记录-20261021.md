# 第四批完善实施记录：同一学习目标下的协作与恢复

日期：2026-10-21。本批继续使用现有架构，落实T04—T05的一部分。目标是让“聊天提出需求—秘书分派—练习—评估—规划—回到聊天”能够关联同一目标，保留真实执行记录。

## 1. 队员现在怎样体验

1. 在线连接后端，进入对话页，提出“帮我安排复习并诊断”等学习需求。普通问候不会自动建立学习目标。
2. 回复下方显示“当前学习目标”：本轮知识点、当前负责角色、等待原因、已发生的交接和下一步按钮。
3. 没有知识点的真实账号会等待补充，导入课程或添加知识点后返回对话，点击继续，沿用原目标。不会为了跑通流程而注入二叉树42分。
4. 当前画像已有相应知识点或课程时，在新对话中明确点名，可以改变本轮选择；没有明确点名时按已有画像选择待练点，并如实显示有无测评记录。
5. 从目标按钮进入练习，题目与交卷携带原目标标识及状态版本。完成后返回对话，查看同一目标的结果与计划变化。
6. “查看调度轨迹”和“评估与重排轨迹”分别打开真实原始记录。后者引用本轮实际评估服务留下的轨迹，不复制事件来增加Agent执行数量。

**一场聊天对应一个目标、一轮交卷。下一轮或改变目标，请使用“新对话”。** 浮标也沿用当前聊天标识，并提供回到对话继续该目标的入口。

## 2. 本批实际实现

- 新增`app/services/learning_context.py`，以现有持久化workflow作为目标实体，`goalId=sessionId`，不再复制一套画像与计划事实。
- 聊天请求通过`coordinateLearning=true`接入；同一账号与聊天标识得到稳定目标，换账号隔离。新增只读恢复接口`GET /api/v1/workflows/chat/{chatSessionId}`。
- 规则秘书依据目标、画像、计划及输入状态调度现有专责模块。交接保存目标ID、Agent子任务ID、依赖、输入引用、约束、输入/输出版本、预期产物、产物引用、证据和实际工具记录；Agent子任务与用户计划任务分开。
- 状态区分等待知识点、等待可用时间、等待答题、需要现场出题、工具失败和本轮完成。当前0分钟预算会阻止继续安排练习，调整时间后可恢复同一目标。
- 等待期间重复点击且输入未变，不增加步骤或重复执行。工具失败保留目标和失败状态，可以手动重试。当前由规则秘书调度，聊天文本或题目本身是否使用模型另行标注，不能据此宣传“多个LLM自主讨论”。
- 目标交卷统一进入现有普通练习提交服务，工作流入口拒绝该类目标直接提交原始答案；随后消费已保存的submissionId完成目标，不重复评估和重排。
- 画像、计划和目标状态版本在模型解析前及最终提交锁内校验。错误知识点、其他账号目标、过期版本、同目标第二份交卷返回404/409，避免错误覆盖。
- 目标绑定与画像、证据、错题本、计划、轨迹及幂等响应一起原子提交。6次并发不同交卷标识，只能有1份成功计入该目标；重复原交卷标识返回原结果。
- 客户端如果漏掉最后一次工作流同步，目标恢复会消费已经绑定的提交。进程重建后，服务端仍能按原账号与聊天标识读取该目标。
- 调度模型不再接收标准答案表、用户答案和题库正文；标准答案保留在服务端判分路径。普通旧接口保留兼容。

## 3. 前端改动

- 对话页增加目标卡片、等待原因、测评证据状态和角色交接展示；明确显示“规则秘书”，不把聊天模型生成文案当作已执行业务。
- 目标入口把目标ID、版本、知识点和题目模式带入练习；交卷后推进明确指定的目标，不消费缓存里其他会话的状态。
- 真实来源资料库仅在相关库唯一时自动优先用于目标练习，否则明确显示通用知识/题库模式。指定文档的资料练习仍可从资料库独立进入。
- 聊天、目标刷新、练习提交与轨迹读取检查当前账号和请求顺序；新对话或离开页面后，迟到结果不回写新的会话。
- 轨迹页支持显式传入traceId，避免始终打开缓存里上一轮评估轨迹。可选目标响应经过实际使用的运行时结构校验。
