### 2. 实际配置本机 PostgreSQL

- 复用既有 Docker PostgreSQL 容器，在其中创建知学专用的 `zhixue_dev` 数据库与非超级用户账号，原有 `papers` 数据库未改动。
- 将连接信息保存在本机被 Git 忽略的 `.env`，更新虚拟环境依赖并执行 Alembic 迁移。
- 停止旧 JSON 后端后备份数据，将 433 条业务与聊天记录导入新库，并逐条核验一致；其中包括 5 个账号和 36 条聊天记录。
- API 与 Worker 分别运行，`/ready` 检查通过；独立临时文件任务被 Worker 实际领取并完成。
- 文件目前使用本地存储，服务目前在开发机运行；这些配置和运行数据不随源码提交。

### 3. 修复聊天历史没有图片

- 旧实现仅持久化提问、回复和部分题干文字，没有保存图片附件。
- 新图片保存私有原文件，历史记录只携带有大小限制的缩略图及附件 ID。
- 新增 `GET /api/agent/images/{fileId}`，检查账号归属后读取原图；返回禁止缓存。
- App 恢复历史时展示缩略图，点击后加载原图；页面关闭、账号切换后拒绝迟到响应。
- 清空历史或历史超过保留上限时回收对应附件；PostgreSQL 模式通过 Worker 执行原文件删除。账号注销沿用已有文件清理流程。
- 纯图片消息也会保存可读的提问文字，避免被历史列表过滤。
- 以前没有保存的旧图片无法从文字记录自动还原，需要重新发送。

### 4. 修复 PDF 切片与阅读展示

- 合并同一标题范围内过短的正文，连接中文断行，修复“稳 / 定性”等被拆开的词。
- 长正文尽量按完整句子切分，并保留上下文；保留章节、页码边界及单片长度限制。
- 正文预览按章节、页码合并连续展示，减少独立碎片卡片；检索仍保留来源片段。
- 对本机刚上传的数值分析 PDF，在确认尚无练习等记录引用、备份旧文档和切片后，将 78 个片段更新为 10 个；保留原文件和已有知识点。
- 其他已上传资料不会自动批量改写；若需要重建，须先核对引用关系、备份并验证。

### 5. 补齐验证与源码排除规则

- 修复测试隔离：显式固定 JSON 测试后端及空模型 Key，避免重新读取开发机 `.env` 后误连日常库或模型。

## 本机日常运行

先启动 Docker Desktop 及 PostgreSQL 容器。后端 `.env` 使用本机真实配置，不要覆盖已有模型设置，也不要提交密码：

```dotenv
APP_ENV=development
ZHIXUE_DB=postgresql
DATABASE_URL=postgresql+psycopg://USER:PASSWORD@127.0.0.1:5432/zhixue_dev
FILE_STORAGE=local
```

首次配置或结构更新时，在后端目录安装依赖并执行迁移；已有账号需用迁移工具导入，不能仅切换连接后当作数据已迁移。

```powershell
cd D:\project\zhixue_final\server\zhixue-agent-server
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m alembic upgrade head
```

日常分别在两个终端运行，两个进程连接同一个数据库：

```powershell
# 终端一：在后端目录运行
.\.venv\Scripts\python.exe run.py
```

```powershell
# 终端二：在后端目录运行
.\.venv\Scripts\python.exe worker.py
```

若已有后台实例，不要重复启动。当前开发机的隐藏进程不是 Windows 服务，重启电脑后需重新启动。`/health` 仅检查进程存活；结合启动日志的 PostgreSQL 仓储标识与 `/ready` 判断数据库就绪。

模拟器连接 `http://10.0.2.2:5000`；真机连接同一网络下电脑的 IPv4 地址。App 在“我的 → 关于”连续点击版本号 5 次，进入接口环境并选择真实后端。

| P0 | 数据与异常恢复验收 | 双账号资料和图片隔离；交卷重复提交只计一次；API / Worker 重启后数据仍在；处理中断任务可恢复；清空历史后原图不可再访问 |
