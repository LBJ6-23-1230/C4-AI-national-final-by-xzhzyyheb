## 本轮确认并修复的问题

1. **认证缺少整体事务**：注册、会话和初始画像分开保存，异常可能遗留半个账号；SQLite 多 worker 同时注册同一手机号、请求验证码可越过唯一性和冷却检查。改为短事务内暂存并一次发布；验证码错误次数在返回业务错误时仍提交，意外异常整体回滚；会话解析拒绝已注销账号。
2. **推荐接口可指定他人身份**：现在共用会话身份解析，登录者不能通过 userId 切换身份，游客不能查询真实账号的薄弱点。
3. **画像更新覆盖并发数据**：聊天更新目标/时间、课程大纲缓存和知识点合并补齐事务；课程缓存、画像和派生计划通过同一暂存批次发布，模型调用在事务外。
4. **知识库解析期间的竞态**：解析后重新核对知识库归属、存在性和文档数量；文档、切片、汇总、画像与计划一次提交，避免删除后复活和半成功。创建和删除也补齐跨进程事务。
5. **错题与资料题并发**：练习次数更新、收藏操作、资料有效性确认及题目保存补齐事务，防止计数丢失和在已删除来源上继续写入。
6. **聊天历史跨 worker 丢失**：读改写增加跨进程文件锁，保留按账号分桶和原子替换。
7. **工作流和 trace 仍只有线程锁**：工作流创建、推进增加可重入的跨进程文件锁；模型请求不持有数据库写事务。trace 追加和工作流评估记账使用短事务。创建会话与 trace 一次发布，无效 autoRun 答案在落盘前拒绝。
8. **启动与输入边界**：启动脚本从自身路径定位工程，检查全部运行依赖和 pip 依赖一致性，支持 -Check/-Port，并恢复调用者目录；run.py --check 不创建运行数据库，dotenv 正确处理 BOM。HTTP 请求限制 16MiB；文档 base64 在解码前限长；课表识别排除非有限学时，日志不打印上游异常正文。
9. **迁移混入旧数据、只读检查创建空库**：默认拒绝覆盖现有目标；显式 --overwrite 在 SQLite 事务内清空并替换，不保留旧记录。SQLite 校验和反向读取使用只读连接，JSON 输出原子替换；拒绝静默跳过无效集合。迁移仍要求先停服并备份。
10. **交付工具泄露本地配置与运行数据**：统一过滤签名材料、数据库及旁文件、账号/聊天文件与备份、依赖和临时缓存；保留 .env.example。打包时去掉 build-profile 的本地签名材料和产品签名引用，原文件保持不变；逐个匹配检查疑似密钥，示例占位符不能使整份文件绕过检查。ZIP 先写临时文件再替换，保留旧的完整包直到新包成功。
11. **工具与仓库布局不一致**：交接包从 项目文档 取文档，包含根启动脚本；不再删除源码目录里的 docs/_probe。旧 build_v2 入口转向当前打包器，默认使用当前构建的签名 HAP；签名、模拟器和密钥别名工具移除旧机器路径/内置签名参数，文档生成写到工程内临时目录。LLM 自检优先使用后端虚拟环境。
12. **联调脚本误判**：清除旧 pytest 报告并检查子进程退出码；隔离实例显式开启开发工具并钉住离线模式；历史隔离使用两个真实登录会话，华为检查断言当前诚实返回未接入；修复相对 --out 路径崩溃和跳过单测却显示 PASS 的输出。后端 README 同步实际认证与并发行为。

13. **LLM 自检假成功**：未配置模型名时改为检查代码默认模型；Embedding 失败会使自检失败，禁用 SDK 隐式重试，不再输出上游异常正文。新增受控 SDK 测试，未发出真实模型请求。

## 仍需单独完成的能力与验收

当前不能承诺“除用户端之外绝对没有问题”。已发现并能在本地复现的上述代码问题已修复，当前自动化检查未发现新的失败；仍有以下实际边界：

- 本轮使用离线规则与受控测试；真实模型、视觉/Embedding 额度与可用性、外部网络和正式部署环境没有本轮实测。还需要设备端交互、通知、语音及正式签名验证。
- 文件锁用于同一台主机的多进程串行；不代表跨多台机器的分布式锁。默认 JSON 仍限单写进程，多 worker 必须切 SQLite。

因此可以进入用户端回归测试，但对外描述应为“本地代码和离线回归通过，外部能力及设备验收待完成”，不能描述为完整生产能力均已验证。
