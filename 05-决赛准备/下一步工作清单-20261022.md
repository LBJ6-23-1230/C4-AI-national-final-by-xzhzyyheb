# 下一步工作清单（第九批候选）

日期：2026-10-22。基线：第八批已完成 PDF 依赖约束、Embedding 10 条分批、模型默认值统一；当前 557 项测试均取得通过结果。

## P0：正确性与资源安全

### P0-1 多进程提交幂等下沉到仓储事务

- 现状：`_SUBMIT_LOCK` 是进程内 `threading.RLock`，多 worker 不能互斥。
- 实施：SQLite 增加 submission 唯一键和原子“占位/完成”事务；JSON 后端明确限制单进程，或实现可靠的进程间锁。
- 验收：2 个服务进程并发提交同一 idempotencyKey 10 次，只产生 1 条 submission，掌握度只增加一次；冲突响应一致。

### P0-2 限制解析后台并发

- 现状：每次交卷新建 daemon 线程，超时后模型调用仍继续。
- 实施：固定大小线程池（建议默认 4）与有界队列；队列满时直接使用确定性解析，并记录降级原因。
- 验收：50 个并发提交下，同时在途解析不超过池大小，线程数与交卷延迟有界。

### P0-3 补解析结果安全回写

- 现状：超过等待预算后返回 fallback，后台 LLM 结果完成后被丢弃。
- 实施：用 submissionId 作为条件更新键；只有记录仍是 fallback 且归属一致时，回写 submission 与 wrong_book，避免覆盖后续修改。
- 验收：慢解析先快速返回 fallback，完成后读取同一 submission 可获得 llm 解析；失败或重复回调不破坏数据。

## P1：性能与韧性

### P1-1 总预算内的瞬时错误重试

- 仅对 429/可重试 5xx 做一次短重试，超时与退避必须计入总预算；认证、参数错误不重试。
- 用桩验证首次 429、第二次成功，以及持续失败时总耗时不超过配置上限。

### P1-2 出题短期缓存

- 按用户、知识点、资料版本、题量建立 5–10 分钟缓存；资料变更或题目已使用时失效。
- 验收同知识点二次进入低于 1 秒，且不会跨账号复用或返回已失效资料题。

### P1-3 复用模型客户端与连接

- 按 base_url、Key 指纹、timeout、retry 配置缓存 OpenAI 客户端；配置变化时重建。
- 连续调用构造一次客户端，测试间可显式清理缓存，不暴露 Key。

### P1-4 决策超时可配置

- 新增 `LLM_DECISION_TIMEOUT_SECONDS`，默认值与整体预算协调；回落时写入结构化日志。
- 验收可从日志区分模型决策与确定性 fallback。

## P2：可观测与工程化

### P2-1 LLM 统一观测

- 每次调用记录 request 类型、模型、耗时、HTTP 状态、token、finish_reason、重试与 fallback 原因；严禁记录 Key、完整题目和用户隐私。

### P2-2 可验证的健康状态

- 将 `llm_ready` 拆为 `configured` 与带缓存的 `verified`；主动探测需限频，不能让每次 health 都产生模型费用。

### P2-3 依赖锁定与干净环境复验

- 在 Python 3.12 新建干净 venv，形成锁定清单；安装后运行 557 项及真实 PDF 用例，记录 SWIG 告警。

### P2-4 数据保留与写盘治理

- 为 traces、submissions、wrong_book 和 history 定义数量/时间保留策略；评估 JSON 全量重写迁移到 SQLite 的默认方案。

### P2-5 前端与设备验收

- 使用 DevEco Studio 完成 HAP 构建、签名、覆盖安装与启动检查。
- 真机覆盖：知识库上传/检索、专项练习出题、交卷幂等、解析 fallback/回写、返回刷新、断网恢复和双账号隔离。

## 建议实施顺序

1. P0-2 解析线程池与 P0-3 安全回写。
2. P0-1 SQLite 多进程幂等事务与并发测试。
3. P1-1 有界重试、P1-3 客户端复用、P2-1 观测。
4. P1-2 出题缓存与 P1-4 决策超时。
5. P2-3 干净环境、P2-4 数据治理、P2-5 设备验收。

## 统一验收口径

1. 后端全量测试在同一可控环境一次通过，不拆分统计。
2. 2 worker 并发 10 次只计分一次。
3. 50 并发提交不产生无界线程，交卷有明确延迟上限。
4. 慢解析可后台安全补回，幂等重放拿到一致结果。
5. 200 切片真实语义检索返回 `hybrid:semantic+keyword+tag`。
6. 日志能还原耗时与降级原因且不泄露密钥和完整用户内容。
7. 新 HAP 构建、验签、安装、启动和核心真机流程均留证。
