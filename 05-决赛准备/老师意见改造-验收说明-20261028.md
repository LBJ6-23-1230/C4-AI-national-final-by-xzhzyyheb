# 老师意见改造验收说明

本次改造基于 2026-10-28 拉取的 main。实现保存在当前工作区，未提交或推送 Git。原有本地修改保留。

## 启动与安装

1. 使用当前工程最新后端，停止旧进程后在 `server/zhixue-agent-server` 执行 `.\.venv\Scripts\python.exe run.py`。
2. 安装 `app/entry/build/default/outputs/default/entry-default-signed.hap`。沿用本机现有签名配置，其他设备可能需要重新签名。
3. 检查客户端连接的是这份后端，确认 `/health` 与 `/ready` 正常。只装新客户端、继续连旧后端时，新增接口不可用。
4. 使用两个真实账号验收搭子功能；第三个账号可用来验证消息隔离。测试过程中不需要再次执行数据库迁移。

新增消息、课程设置、报告和行动清单使用现有仓储与 PostgreSQL compatibility_records；不新增表，不变更 `20261028_02` 数据库结构，不在启动时执行 DDL。

## 八项验收路径

| 项目 | 操作 | 预期 |
|---|---|---|
| 串行学习入口 | 新账号进入学习建议/学习页，点击建立档案，导入课程，再点“下一步：确认目标与考试日期” | 先完成课程及目标，保存后才出现补充知识库、拍照错题及开始测评入口 |
| 拍照逐题入本 | 上传多题图片，逐题切换，核对题干、课程、知识点，只加入部分题 | 每题可独立加入；重试不重复；收藏不计答错，不降低掌握度 |
| 分科专项练习 | 进入专项练习，切换数据结构、计算机网络等课程 | 列表只展示当前课程知识点；后端拒绝课程与知识点不匹配的请求；题目不足时不拿别科题补齐 |
| 单科雷达 | 打开知识画像，通过图下方课程按钮切换 | 雷达、薄弱点列表及后续练习保持同科；少于 3 个有效维度时展示卡片；未测评不伪装成零分薄弱 |
| 搭子协作 | A 邀请 B，B 接受，双方从搭子卡片进入聊天 | 展示结伴日期及天数；文字和图片可发送；语音转文字进入草稿；打气/督促快捷语只填入草稿，由用户发送 |
| 阶段/考前闭环 | 在课程目标页设置近 14 天内的考试日期，进入学习页及“阶段复盘与考前建议” | 出现考前提醒；建议读取分科学习证据、历史及考试日期；用户确认后加入行动清单，可跳练习、记录完成、再评估 |
| 错题本分层 | 科目→知识点→题目，点击返回逐层退回 | 不默认铺开全部题干；刷题只覆盖当前知识点，保留原有累计答对 3 次移出规则 |
| 多智能体协作 | 在对话学习目标卡、练习评估结果查看“学习助手协作进度” | 展示真实轨迹的角色、状态、产出；可进入同一 trace 的交接与调整依据，不使用模拟完成动画 |

## 需要特别确认的行为

- 语音为“语音转文字”，不是语音消息。需在目标设备授权麦克风，并确认系统识别能力可用；权限被拒绝或识别不可用时，保留文字入口。
- 图片限 JPEG/PNG/WebP，客户端提示约 2MB 上限；发送前预览，失败保留草稿，可重试。
- 拍照识别题在未确认标准答案时提供题干和解析回看，不直接自动判分；可跳转同知识点生成练习，避免把模型解析当作可靠评分标准。
- 阶段建议明确标注“模型结合证据生成”或“规则建议”。模型不可用时降级为规则；没有测评记录时先建议诊断，不编造进步或考试预测。
- 行动清单由用户确认后添加，不覆盖已有计划。用户点“已完成”只记录完成，不直接提高掌握度；实际练习评估才更新画像。
- 考前提醒在应用学习页面展示；不新增系统推送或后台定时服务。报告在用户请求时生成，同日同证据复用已保存报告。
- 搭子聊天采用增量轮询，最多每页 10 条；只允许有效双方关系访问。兼容已有多搭子联系人，每位搭子独立消息会话。
- 不能由空闲时段数量推断“协作可靠度”；现在无已验证协作记录时该项为零。匹配分数因此可能低于旧版本。

## 验证方式与范围

自动化包括后端全量 pytest、新增消息/图片/逐题收藏/课程约束/考试日期/报告任务隔离测试、前端 ArkTS 编译与 HAP 打包、接口声明与前端校验覆盖检查。测试使用隔离仓储，最终回归禁用本机 .env 自动加载，避免误连本地配置中的外部服务。

真机麦克风、相册权限、双设备联机、真实模型输出质量及实际用户学习后的建议效果，需要按上表进行验收；编译通过不等同于这些设备交互已验证。PostgreSQL 专项测试如未配置专用测试库会跳过，不能视为共享库上的实际联调通过。

自动化最终结果以交付消息及 `.local-work/upgrade-pytest-final.log`、`.local-work/upgrade-build-final.log`、`.local-work/upgrade-validator.log` 为准。
