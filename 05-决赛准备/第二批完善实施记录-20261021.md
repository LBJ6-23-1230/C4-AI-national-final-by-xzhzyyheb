# 第二批完善实施记录：计时恢复、原子提交和输入驱动重排

日期：2026-10-21。继续在现有未提交工作区上实施，保留首轮访问控制、第一批完善和本机签名配置。此记录对应T03的恢复能力、普通提交可靠性及T06的部分实现，不表示总方案全部完成。

## 1. 活动计时与结算草稿恢复

- 增加持久化的FocusRuntime：原账号、稳定专注ID、任务、累计时间、计时锚点、暂停与中断次数。计时计算由实际使用的FocusClock模块统一处理。
- 应用重新读取账号快照后，可以恢复同一专注ID；暂停期间不累计，未暂停期间按时间戳累计，倒计时不会超过原计划时长。
- 倒计时后台到期后恢复，完成时间按计时事实计算，不能把恢复应用的时间写成学习完成时间。
- 结算前先把结果草稿持久化，再离开计时页；修改自评也保存草稿。保存失败保留原状态并提供错误提示。
- 聊天页提供恢复入口，专注设置页可选择恢复计时或未保存结算；显式确认后可放弃上次未保存记录。存在恢复记录时不静默覆盖为新专注。
- 切换账号仅清内存并恢复新账号快照，不把旧账号的计时或草稿写入新账号。结算记录使用原稳定ID，重复保存不重复计入。
- 已完成“实际状态模块+存储模块”的转译执行测试；系统进程回收、锁屏和原生Preferences的设备行为仍需真机/模拟器验证。

## 2. 普通练习提交一次性发布

- 增加StagedRepository，业务代码先在可读写的隔离副本中收集变更，最后由原仓储apply_batch一次发布。
- 普通提交的画像、证据、错题本、规划、计划差异、事件、trace和幂等响应一起提交。
- 错题本或规划计算中断时丢弃暂存变更；最后写盘失败时回滚；成功提交后响应丢失时，重试直接返回原响应，不重新请求解析或重复更新。
- JSON和SQLite均覆盖异常测试。该机制提供这次业务写入的原子发布；读—决策阶段仍依赖现有同进程业务锁，不据此宣称多进程串行化已完成。

## 3. 可用时间能够改变专项计划

- 新增`POST /api/v1/plans/current/availability`，请求包含可用分钟数、预期计划版本和幂等键，账号由有效身份解析。
- 实际调用规划Agent与fit_plan_to_budget工具，按预算安排完整任务；超出预算的任务保存在unscheduledTasks，并显示原因，不丢弃、不标为完成、不暗改DDL。
- 前端学习计划页可输入分钟数或使用30分钟快捷操作，查看已安排、剩余与暂未安排时长及计划差异。离线Fixture明确说明此操作需要连接服务。
- 改回较大的预算会重新纳入保留任务，保持任务ID与完成状态；0分钟只保留完成历史，待办任务移入暂未安排区。
- 评估后的重排继续遵守已保存预算。例如原算法全错后可能产生55+15分钟，设置60分钟预算后只安排能容纳的任务，其余明确保留。
- 已完成的任务不再被重排算法修改时长；专注完成了已移出本次安排的任务，也能记录其完成事实并更新预算摘要。
- 输入携带版本检查，过期版本或冲突幂等键返回409。前端计划ViewModel拒绝切换账号后的迟到结果和更旧的计划版本。

**明确范围：本次是“专项任务总分钟数”约束。课程DDL仍分区管理，尚未实现课程占用、具体空闲时段和截止日期的统一日历排程。** 系统目前保留完整任务，不自动拆分或缩短任务。预算不足以安排任何任务时，需要用户增加时间或后续选择其他安排。

## 4. 新课程、资料知识点进入已有计划

- 之前仅“无计划时首次生成”的逻辑，改为新增知识点后更新当前账号的原计划。
- 保留原任务ID、时长、已完成状态和暂未安排项；新增知识点生成新任务。若已有时间预算，继续经过规划Agent校验预算。
- 画像发现、计划变更、版本差异、KnowledgePointsDiscovered事件和规划trace统一提交；失败不留下新增画像却没有新计划的部分状态。
- 同样课程重复导入不会重复创建任务或增加计划版本。
- 这条链路让资料中的新知识点影响规划，**尚未把资料检索片段接入出题与解析**。

## 6. 队员可复验的场景

1. 登录真实测试账号，开始30分钟专注，暂停后结束应用进程；重进同账号，从聊天页恢复，确认仍暂停、ID与已计时间保持。
2. 未暂停时结束进程，再进入后检查已用时间；倒计时已过期时进入同一结算，完成时间应对应原到期时刻。
3. 进入结算页选择“部分完成”，未保存前结束进程；重新进入恢复草稿，保存后再重进，历史只有一条。
4. 甲账号保留未完成专注后换乙，乙不应看到甲的恢复入口；换回甲恢复原记录。
5. 计划页先设60分钟，再改30分钟；查看版本差异和暂未安排任务，再设回60分钟，原任务ID与完成状态保持。
6. 设60分钟后提交低分题组，检查后续重排不超过60分钟；注意该预算只覆盖专项任务。
7. 新账号先导入数据结构，再导入操作系统，比较原计划及新版计划；第二门课程的任务应出现，已完成任务保留，重复导入不增加版本。

后端可在隔离测试仓储中复验，不要在真实用户数据上执行故障注入或重置。
