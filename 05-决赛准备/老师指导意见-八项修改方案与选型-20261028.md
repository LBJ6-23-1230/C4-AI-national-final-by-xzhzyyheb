# 老师指导意见：八项修改方案与选型

日期：2026-10-28。状态：团队评审稿，尚未实施。

本稿依据老师意见、所附页面截图和当前仓库代码整理。目标是把“导入学习信息—诊断—规划—学习练习—评估—调整—考前建议”连成一条可验证的学习路线，同时改善课程分类和搭子协作。

## 一、建议先确定的整体方案

推荐组合：串行引导 + 逐题确认入本 + 统一课程分类 + 单科雷达切换 + 规则匹配与搭子聊天 + 基于证据的阶段总结 + 真实智能体协作时间线。

| 问题           | 推荐方案                          | 实施优先级      | 工作量相对判断 |
| ------------ | ----------------------------- | ---------- | ------- |
| 1 学习目标入口并列   | 分步骤引导，知识库放在基础信息之后             | P0         | 中       |
| 2 拍照题目不能逐题入本 | 每题独立保存，支持批量勾选                 | P0         | 中       |
| 3 专项练习跨课程混排  | 课程选择后再选知识点                    | P0         | 中       |
| 4 雷达图跨学科混排   | 单科雷达，下方切换课程                   | P0         | 中       |
| 5 搭子功能浅      | 可解释规则匹配 + 双向关系 + 文字/图片/语音输入聊天 | P1         | 大       |
| 6 学习没有长期闭环   | 每周总结 + 考前节点建议 + 建议转任务         | P1         | 大       |
| 7 错题本列表冗长    | 科目→知识点→错题三级结构                 | P0         | 中       |
| 8 多智能体协同不明显  | 关键节点展示真实协作状态、产出和调整原因          | P1，与闭环共同实施 | 中至大     |

P0 是建议先实现的基础功能，不代表 P1 可以从最终版本中省略。先统一分类和学习证据，再做长期建议，才能避免建议引用错误课程或不可靠分数。语音权限与设备能力建议提前验证。

## 二、共用基础：先统一课程、知识点和证据

问题 3、4、7 应共享同一套课程归属规则，而不是在三个页面分别猜学科。

- 课程有稳定的 courseId 和显示名称；知识点有 knowledgePointId，并明确关联课程。
- 同名知识点不能仅凭文字合并。例如两门课中的“树”不能自动当成同一个学习对象。
- 导入、拍照识别、出题、提交答案、画像更新和错题入本都要传递课程与知识点标识。
- 兼容现有 sourceCourse、courseName 数据，先整理映射；不能识别的放“待确认分类”，允许用户修正，不能静默归入其他课程。
- 每条评估证据至少记录用户、课程、知识点、来源、时间、结果及关联任务/题目；记录生成建议时使用的证据版本。
- 上传课程仅说明“需要学什么”，不能证明“学得如何”。没有测评证据时标注“未测评”，不要显示成“0 分薄弱”。

当前代码已有课程名称处理服务、知识画像、练习和错题记录；稳定标识及旧数据兼容仍需实施前完整盘点。涉及持久化字段或新增实体的地方，要评审迁移，不能假设只改前端即可。

## 三、问题 1：学习目标改为串行引导

### 推荐 A：有状态的步骤引导

首次进入且没有课程、DDL、错题时，只突出一个主按钮“开始建立学习档案”，进入以下步骤：

1. 建立课程：上传课程信息或手动添加，识别后让用户确认课程名称。
2. 设置目标和时间：填写目标、考试日期或 DDL；没有日期可选“暂不设置”，可用时段也可稍后补充。
3. 补充材料：上传讲义等知识库资料，可选；有错题可进入拍照诊断，可跳过。
4. 确认结果：展示课程、目标、时间与材料摘要，再生成初步学习路线。

知识库入口出现在课程和 DDL 流程之后，不再与它们在空状态首页平级。这里的“串行”是界面主线串行，不要求所有人必须同时上传课程、DDL 和错题才能使用。

已有部分资料时显示“继续完善第 X 步”，避免重新上传；已有完整档案时显示当前路线和“管理课程/补充资料”次级入口。只有错题的用户可由识别结果确认课程后接入流程。

### A，步骤状态更清晰，答辩容易展示。验收：新账号不再看到三个同级上传按钮；中断重进能继续；跳过可选步骤后仍能形成初步计划。

## 四、问题 2：拍照识别的每道题都可选择加入错题本

### 推荐交互

- 每道识别结果都有独立的“加入错题本”按钮或复选项；单题、两题、多题完全一致。
- 多题页面可增加“选择题目”和“加入已选 X 题”；默认不自动全选保存。
- 保存成功后该题显示“已加入”，失败时保留识别结果并允许重试；切换题目不丢失各题状态。
- 保存前可以修正题干、课程和知识点；识别不完整时提示补充，不能把解析文字当成可用题干。
- 保存后可“去错题本查看”或“练同类题”；加入错题本与加入复习计划是不同操作。

### 必须明确的数据规则

识别批次和批次内每题需要稳定标识，重复点击或重试不能重复入本。保存题干、题型、图片引用、课程、知识点和解析；相同图片中的不同题不能合并成一条。

大模型识别不代表已确认标准答案。答案未确认的题可以收藏回看，但不能直接按不可靠答案自动评分；开放题、公式题需要对应的作答和评估方式，不能全部硬转选择题。

用户主动收藏不计为“答错一次”，不直接降低掌握度。真实作答错误才产生相应评估证据。

验收：上传包含 6 道题的图片，只保存第 2、5 题，重进错题本恰好存在这两题；重复请求不增加副本；两个账号之间无法读取对方题目。

## 五、问题 3：专项练习按课程隔离

### 推荐 A：课程选择→知识点列表→专项练习

顶层显示课程卡片，卡片展示待测评知识点数、已确认薄弱点数及临近考试信息。进入某门课程后，仅显示本课程知识点，再选知识点开始练习。

来自某门课程画像或错题的跳转，直接选中相应课程和知识点。返回时保留筛选状态。

### 备选 B：同页课程标签切换

顶部横向课程标签，下面显示该课程知识点，跳转少。课程多时需增加“全部课程”选择器，不能让标签无限横向堆积。

推荐：手机端采用 B，课程很多时使用课程选择器；若现有页面拆分更方便，采用 A，后端规则相同。

出题请求必须绑定课程与知识点，后端校验归属；材料检索也限定课程。某课程题目或材料不足时提示补充资料，不能从别的科目拿题补齐。未测评知识点入口叫“开始测评”，有证据的薄弱点才叫“专项补强”。

验收：切到计算机网络后，列表、题目、来源材料、结果回写都属于该课程；不能出现数据结构题混入。

## 六、问题 4：雷达图按学科切换

### 推荐 A：一个雷达图 + 下方课程按钮

图上方标明当前课程；图下方放课程按钮，切换后同步更新雷达图、薄弱点列表、建议和“开始练习”的课程上下文。记住上次选择；首次优先选择用户当前正在学习的课程。

同科知识点过多时，建议先建立 3～6 个稳定知识模块，例如数据结构中的线性表、树、图、查找、排序，再下钻具体知识点。模块划分需要确定映射规则，并区分未测评数据。

短期若直接使用具体知识点做轴，固定每门课的轴和顺序；不要每次按最弱的 6 个点重排，否则前后图形不可比较。更多知识点在下方列表展示。

### 备选 B：每科一张缩略雷达卡

课程之间可以直接浏览，但屏幕占用大、手机标签拥挤。更适合作为平板或总览页，不作为首版主方案。

边界：少于 3 个有效维度时用条形图；没有证据时显示“未测评”，不能补造分数凑图；前后对比必须使用相同轴。当前画像分数与考试目标分数不是天然同一尺度，不能简单把“期末 80 分”画成“掌握度 80”的目标线。

验收：课程切换后没有跨学科维度；无数据不画虚假掌握度；对比图轴保持一致。

## 七、问题 5：学习搭子从匹配入口升级为协作空间

### 5.1 匹配标准的备选方案

| 方案            | 做法                         | 优势               | 代价/限制                 |
| ------------- | -------------------------- | ---------------- | --------------------- |
| A 可解释规则，推荐首版  | 共同课程、目标、可用时间、能力互补等结构化评分    | 可测试，结果稳定，可展示匹配依据 | 需要清洗课程和时间信息           |
| B 规则筛选 + 模型解释 | 先按 A 排序，再由模型解释已确认事实、建议共同任务 | 对话更自然            | 需要校验模型不编造候选人特征        |
| C 模型直接排序      | 模型比较候选档案并排序                | 可处理自由文本偏好        | 成本、延迟和排名稳定性更难控制，不推荐首版 |

建议 A 起步，后续叠加 B。评分参考：共同课程 35、目标兼容 20、时间重合 25、能力互补 15、经真实行为验证的协作可靠度 5。权重是待验证的产品参数，不是已证明最优。

先满足愿意匹配、真实账号、非本人、关系状态有效等条件。知识互补只依据实际测评；缺失项显示“未知”，展示资料完整度，不编造中性得分或把“只填一个空闲时段”当作稳定可靠。

为用户提供“同进度一起学 / 优势互补互相讲解”两种偏好。结果展示具体原因，如“共同学习数据结构，周二晚重合 60 分钟”。时间需包含星期，不能只比较每天时刻。无合适人选时说明原因并引导补充偏好。

### 5.2 匹配成功与建立关系的定义

推荐成功不等于成为搭子。双方通过已有邀请流程确认后才建立有效搭子关系，记录服务端 acceptedAt，并据此展示“成为搭子于 10 月 28 日 / 已结伴 X 天”。不能使用推荐生成时间或页面本地时间代替。

首版建议一个有效搭子，减少关系复杂度；如果团队决定允许多个，则每个搭子独立会话和关系。无论选哪种，都需处理重复邀请、双方同时接受、解除关系等情况。

### 5.3 搭子页面与聊天

有搭子时展示昵称、共同课程、结伴日期、“与搭子聊天”、共同任务及邀请/关系管理入口。

聊天至少包含：

- 文字输入和发送，消息记录跨设备保存，失败可重试，重复重试不生成多条。
- 图片选择、上传、预览和发送；只允许关系双方访问图片和消息。
- 语音输入：默认解释为语音转文字，识别后放入输入框，由用户修改并发送；录音权限被拒绝时仍能用文字。
- 如果老师希望的是语音消息，则需另做录音上传、时长显示、播放和存储，不等同于语音转文字，建议作为独立选项确认。
- 督促/打气按钮，例如“现在一起专注 25 分钟吧”“今天的任务完成了吗”“这道题我们一起想想”。点击只填入草稿，绝不自动发送；已有草稿时采用用户可见的插入或替换操作。
- 显示未读、发送中、已发送和失败状态；历史消息分页，断线重连后补齐。

首版消息同步可选“增量轮询”（接入快、需控制频率）或 WebSocket（及时性好、连接管理更复杂）。推荐先增量轮询跑通双账号持久化消息，再视现有部署能力选择升级。既有 AI 对话可以复用输入组件，但不能当成人际聊天的消息服务。

加分项：把某项复习任务分享为聊天卡片，双方分别确认参与和完成；无需把原始个人成绩默认共享给对方。

验收：两个真实账号完成邀请确认后看到同一结伴日期；文字、图片、语音转文字能完成发送接收；打气按钮只填草稿；第三个账号不能读取消息或附件；解除关系后不能继续发送新消息。

## 八、问题 6：长期学习与考前建议形成闭环

### 方案对比

| 方案       | 触发与产出                       | 评价                     |
| -------- | --------------------------- | ---------------------- |
| A 阶段复盘   | 用户点击或每周生成阶段学习报告             | 容易先做，有积累但考前针对性有限       |
| B 考前节点建议 | 根据明确考试日期，在考前 14/7/3 天生成分科建议 | 对应老师要求，推荐与 A 组合        |
| C 持续自适应  | 每次有效测评后检查是否需要调整计划           | 闭环最强，需限频、版本和冲突处理，分阶段加入 |

推荐 A+B，先打通“有效测评→画像更新→必要时重排”，再扩大 C。DDL 与考试日期分别标注事件类型，不把作业截止日当期末考试日。

### 具体闭环

导入课程和考试时间 → 初始诊断 → 分科计划 → 学习/练习 → 评估并记录证据 → 更新画像 → 复习与必要重排 → 周总结/考前建议 → 用户确认转为任务 → 执行后再评估。

建议必须包含：当前进展、优先处理的知识点、证据依据、剩余可用时间、分天行动和完成后的检验方式。例如“最近两次图算法测评仍有失误，距考试 7 天，今天安排 20 分钟概念复习和 3 道验证题”。该文案仅为格式示例，实际数量和结果必须来自真实记录。

大模型读取按课程汇总的结构化证据和必要材料，生成可校验的建议；不能仅依赖聊天记录声称“了解用户”。生成结果保存报告版本、时间、使用的画像/证据版本和来源引用。模型不可用时给出明确的规则建议，不能伪装模型生成成功。

数据不足时给“先做诊断测评”的行动，不给虚假的能力结论或考试分数预测。新增建议不自动覆盖用户已确认任务，展示变化并由用户确认；已完成任务保留。定时建议要有去重键，避免同一节点反复生成。

验收：一组有真实练习过程的测试账号能得到引用对应记录的考前建议；零数据账号得到诊断引导；建议能转为任务，任务完成后形成新证据并影响后续建议。

## 九、问题 7：错题本改为“科目→知识点→题目”

### 推荐 A：逐层进入

错题本首页仅展示课程卡片，例如“数据结构 · 5 个知识点 · 12 道待巩固题”。点击课程显示知识点及题目数量，再点击知识点进入该组题目。列表分页或按需加载，不默认展开全部题干。

开始刷题只取当前知识点对应题目，保留现有作答、判分及掌握移出规则。返回后保留原来的课程与知识点。

### 备选 B：课程与知识点二级折叠

改动可能较小，但展开多个分组后仍会很长，适合短期过渡。最终推荐 A。

多知识点题目保存一份，通过主知识点归类，附加知识点作为标签；若允许多处出现，要明确总数按题目去重。无法分类的题放“待分类”。搜索可全局检索，但结果始终显示课程和知识点路径。

当前后端有按课程归组和累计答对 3 次移出逻辑；本次分类调整不擅自改为“连续答对 3 次”。若需要改变记忆算法，应独立评审。图片识别题还要与题型能力对接，不能假设都支持现有选择题刷题。

这里节省的是屏幕空间与操作成本，不代表数据库存储会自动减少。

验收：初始页不铺开所有题；同科不同知识点可分别进入；刷题不越组；重复入本不重复计数；现有掌握移出规则仍正常。

## 十、问题 8：让多智能体协同贯穿学习过程

现有代码包含 secretary、diagnosis、planner、exercise、assessment 智能体，已有 orchestrator 和 AgentTrace 页面。应展示它们实际如何接力，不只增加几个头像或模拟“正在思考”的动画。

### 展示方案

| 方案        | 呈现方式                    | 建议                  |
| --------- | ----------------------- | ------------------- |
| A 关键节点协作卡 | 当前任务下显示负责角色、状态、结果和下一步   | 推荐作为日常界面            |
| B 协作时间线   | 可展开查看每个智能体的输入摘要、结果和交接原因 | 推荐复用现有轨迹页做答辩与追溯     |
| C 多角色群聊   | 每个智能体以聊天消息发言            | 可读性容易下降，重复文本多，首版不推荐 |

推荐 A+B。页面展示用户可理解的工作结果，详细记录进入轨迹页；不把内部技术字段铺到主界面，也不展示模型隐藏推理。

### 一条建议演示链路

1. 秘书：接收“数据结构期末复习”目标，检查课程、考试日期和学习记录是否齐备；不足时请求补充。
2. 诊断：依据真实测评与错题证据，给出该课程画像；仅上传材料时先标记待测评。
3. 规划：结合薄弱点、考试时间和可用时段，生成可执行任务。
4. 练习：按指定课程/知识点选题或基于材料生成题目，校验后交给用户。
5. 评估：用户提交后评分、记录证据、更新知识掌握状态。
6. 秘书协调：根据评估是否达到重排条件，转给规划调整或安排下一次复习。

最有说服力的展示是“原计划今天复习树；测评发现图算法仍需补强；评估把证据交给规划，规划提出调整，用户确认后计划改变”。必须用真实状态验证这条链，而非写死一段说明。

事件记录建议包含 workflowId、traceId、角色、输入数据版本、产出引用、开始/结束时间、状态、交接目标与简短业务原因。失败、重试、等待用户和规则回退也应如实呈现。每次操作不是都必须调用全部智能体；独立读取可并行，有依赖的诊断→规划等步骤按顺序执行。

验收：从卡片能跳到同一任务的真实轨迹；评估后确实更新画像并触发适当后续动作；失败不能显示全部完成；没有用户提交不能展示已完成测评。

## 十一、实施顺序和团队分工建议

### 第一阶段：数据归属与用户操作闭环

明确课程/知识点标识与旧数据映射；完成串行引导、逐题入本、分科练习、单科雷达、三级错题本。优先修正“未测评=0 分”等可能误导后续建议的问题。

### 第二阶段：搭子可用

规则匹配优化→双向关系与结伴时间→文字聊天与消息持久化→图片→语音转文字→草稿快捷语。语音能力、权限、真机输入和附件访问应提前做技术验证，不能到最后才确认可用性。

### 第三阶段：长期建议与协同展示

学习证据汇总→周总结→考试节点建议→建议转任务→评估后重排→协作卡和轨迹联动。报告生成和评估必须使用同一课程归属、同一证据数据。

可按实际人数分配前端交互、学习业务后端、搭子消息后端及联调验收职责；本方案不预设人员或承诺未经估算的工期。数据库变更统一维护迁移，禁止多人对共享数据库分别手改表。

接口变更需同步根目录和 app 中的 OpenAPI 契约。新增数据库结构、消息和附件存储、旧数据转换、权限隔离及失败重试都计入工作量。

## 十二、最终选型建议与端到端验收

建议团队先确定以下选项：

1. 引导采用分步页 A，还是同页渐进展开 B；推荐 A。
2. 专项练习采用课程卡片，还是标签切换；推荐标签切换加课程选择器。
3. 雷达先采用固定知识点轴，还是建设知识模块；推荐首版固定轴，知识模块在映射规则确定后升级。
4. 搭子采用单有效关系还是多关系；推荐首版单有效关系。语音采用转文字还是语音消息；推荐转文字，若两者都要需分别排期。
5. 匹配采用规则 A，还是规则加模型解释 B；推荐先 A 后 B。
6. 长期建议采用周总结加考前节点，协同展示采用关键卡片加真实轨迹。

完整演示：新账号建立课程和考试日期→补充资料→初始测评→单科画像→按知识点练习→拍照识别后选择部分题入本→按科目/知识点复习→两个账号结伴并聊天→查看阶段/考前建议→确认调整任务→完成任务并看到新评估和协作轨迹。

验收同时覆盖新账号、旧账号、无数据、识别多题、跨课程同名知识点、双账号隔离、断网重试、模型不可用和旧数据兼容。所有“已经完成”“已经发送”“掌握提升”必须对应持久化记录或有效评估，不能只由前端切换状态。
