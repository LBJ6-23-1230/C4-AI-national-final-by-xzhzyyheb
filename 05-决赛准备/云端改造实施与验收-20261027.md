## 实际验证

1. **完整后端回归 730 项通过，0 失败、0 错误、0 跳过**，用时约 111 秒。包括原有 JSON/SQLite 业务和真实 PostgreSQL 集成测试。证据：`evidence/deployment-final-20261027.xml`。
2. **另外 1 项独立进程恢复测试通过**：领任务的进程直接退出，租约到期后启动 `worker.py --once`，原任务第 2 次领取成功完成。证据：`evidence/worker-process-recovery-20261027.xml`。
3. **真实 PostgreSQL + 讲解任务专项 32 项通过**，包括跨进程交卷幂等、跨连接领取互斥、事务回滚、归属外键、会话摘要持久化、聊天隔离、注销与原文件清理、最后一次任务崩溃的终态处理。证据：`evidence/postgresql-final-20261027.xml`。
4. **实际备份恢复演练通过**：8 类人工旧记录及聊天记录试运行导入、事务写入、pg_dump 导出、恢复到新库，逐条一致，恢复待补记录数为 0。证据：`evidence/postgresql-migration-restore-20261027.json`。
5. **HarmonyOS debug 构建成功**：资源编译、ArkTS 编译、PackageHap 完成；生成 `app/entry/build/default/outputs/default/entry-default-unsigned.hap`，3,594,577 字节。证据：`evidence/harmony-build-20261027.json`。此包未签名，当前连接开发环境，不是上架包。
6. **前端请求恢复 24 项通过**：账号切换、隐藏页面、旧请求回流、交卷重试保留原幂等键等；生产地址/Fixture/旧配置隔离、登录持久化和结果标签检查通过。
7. 前端契约覆盖检查 `--strict` 通过；新增后台解析状态、画像版本参数及原文件下载接口已同步两份契约。Compose YAML 可解析，确认 API/Worker 无公网端口和迁移服务为单次工具；本机没有 Docker，因此未做 Linux 容器运行验证。

测试模型调用均使用确定性替身或未配置状态，**没有把结果当成真实云模型性能**。PostgreSQL 使用本机隔离的 17.11 实例；没有连接正式用户数据库。

## 构建环境问题及复现

本机 DevEco SDK 的资源编译器加载图片转码 DLL 失败，单加 PATH 无效。通过**工作区内的工具链副本**把依赖放到资源编译器目录后构建成功，未修改已安装的 SDK。

```powershell
# 当前机器上的验证方式；工具链副本位于 .local-work，源码打包会排除。
powershell -NoProfile -ExecutionPolicy Bypass -File tools/prepare_sdk_workspace.ps1 -DevEcoHome 'D:/DevEco/DevEco Studio'
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build_phase9.ps1 -DevEcoHome 'D:/DevEco/DevEco Studio' -SdkHome "$PWD/.local-work/sdk-build-isolated"
```

构建仍有项目已有的 ArkTS 弃用/可能抛异常警告；没有正式签名配置。没有替换 `hap/` 目录中的历史签名包，以免将未签名或旧环境产物冒充新版可安装包。

- 逻辑备份恢复已演练；云平台时间点恢复、主备切换、OBS 文件恢复和 RPO/RTO 未实测。
- 上传与数据库之间存在跨系统崩溃窗口，需要上线前补齐 OBS 清单对账及孤立对象处理。文件删除永久失败会保留失败任务，需要监控和处理。

- 生产域名、云账号、数据库和存储凭据、开发者主体、隐私/支持页面及发布签名需由队伍配置。当前源码保持 development，避免以占位域名阻断现有联调。
