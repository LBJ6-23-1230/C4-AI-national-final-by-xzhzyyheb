# 第五批完善实施记录：空账号入口贯通与目标状态如实呈现

日期：2026-10-21。对应《下一步完善总方案》T04／T05／T08 中"入口与空状态"部分，以及《队员开发交接》第 3 节列出的 P0。

本轮处理的直接现象是用户截图里的那一页：从聊天回复的"学习建议"卡片进去，看到「暂时无法读取学习建议 / 你还没有学习计划」，页面上只有「重新加载」。复核后确认这里有**两个独立缺陷**，症状却长得一样：

1. 后端把"缺知识点"这个等待态的动作指向只读的学情画像页（`pages/StudyTags`），空账号点进去仍然没有知识点可看 —— 用户被告知"要补充"，却无处可补；
2. 计划页把"还没有计划"（正常状态）说成"无法读取"（故障状态），只给"重新加载"—— 而重试永远不会让计划凭空出现。

顺带修掉三处会在真实交互里立刻暴露的状态缺陷：返回页面不刷新、目标查询接口在旧会话上返回 `200 + null`（违反契约）、聊天页对"服务端根本没给目标"这件事没有任何说明。

⚠️ 本记录描述当前工作区的修改。**本机没有执行后端全套 pytest、前端 hvigor 构建、模拟器／真机安装**（原因见第 5 节），所以"已改"不等于"已验收"。没跑过的项都在第 3、7 节如实标出，请勿据此宣称总方案完成。

## 1. 队员现在可以体验的流程

1. 注册一个空账号（不勾选演示数据），进入对话说"帮我安排复习"。
2. 回复下方出现「当前学习目标」，状态为"等待补充知识点"，按钮是「补充课程与知识点」。
3. 点击后**直接进入课程导入页的「导入」标签**（`pages/CourseImport`，`initialTab: 'import'`），不再是只读的学情画像页。
4. 导入一门课程后返回对话：目标卡自动刷新为「继续本目标练习」，不必再手工点一次重试。
5. 若从「今日学习建议」进入且账号确实没有计划：标题是「还没有学习计划」，给出三条可执行入口 —— 导入课程、上传讲义、去对话建立学习目标。只有真的连不上服务时才出现「重新加载」。
6. 计划里任务全部完成时，页面说「本次计划已全部完成」，不再把第一项已完成任务重新推荐成"立即专注"。

## 2. 本批实际改动

### 2.1 后端：空账号的目标动作指向可执行入口

`app/services/learning_context.py` → `action_for()`

- 缺陷：`waitingFor == "knowledge_points"` 返回 `pages/StudyTags`（只读画像页）。空账号进入后仍然没有任何知识点，唯一可点的还是"重试"。
- 改法：返回 `pages/CourseImport`。该页的课程导入会经 `POST /api/v1/profile/<userId>/knowledge-points` 写入 mastery，并由 `app/tools/profile_merge.py` 生成／更新计划 —— 这是这个等待态唯一能真正解除阻塞的入口。
- 保留：按钮文案「补充课程与知识点」不变；`available_time` 仍指向 `pages/StudyPlan`（可用时间输入在那里）；`completed` / `error` / 其它等待态不动。
- 未改契约：`LearningContext.action.targetPage` 在 `openapi.json` 里就是普通字符串（非枚举），换目标页不需要契约变更。

### 2.2 后端：没有目标协调状态的会话不再回 `200 + null`

`app/api/workflows.py` → `GET /api/v1/workflows/chat/<chatSessionId>`

- 缺陷：`learning_context.snapshot()` 在 `state.coordination` 缺失时返回 `None`（历史版本 `/api/v1/workflows` 建出来的会话就是这种），路由原样 `jsonify(None)` —— HTTP **200**、正文 **`null`**。契约声明 200 必须是 `LearningContext` 对象，前端按契约校验后只能报"结构与契约不一致"，既说不清事实（这个聊天没有目标），也不会清掉上一张目标卡。
- 改法：`snapshot()` 为空时返回 404 `learning goal not found`，与"该聊天还没有目标"一致。前端既有的 404 分支会清空目标卡。
- 与启动自检一致：`/api/v1/workflows/chat/handoff-route-probe` 这类不存在的聊天标识，现在稳定是 404 + `learning goal not found`。

### 2.3 前端：计划读取结果分四类

`viewmodels/PlanViewModel.ets`

- 新增 `kind: 'ok' | 'no_plan' | 'error' | 'identity_changed'`，`errorMessage` 原样保留（三个调用方都兼容）。
- 404（或 `NOT_FOUND`）→ `no_plan`，同时 `ClientCache.invalidateCurrentPlan()`：服务端明确说"没有计划"时，缓存里的旧计划必须作废，否则"当前计划"页显示为空、别的页面还拿着上一份计划渲染任务，两处自相矛盾。
- 其余失败 → `error`；请求期间换账号 → `identity_changed`（不再和"没有计划"混在一起）。

### 2.4 前端：「今日学习建议」按事实分状态

`pages/StudySuggestion.ets`

- 四种状态：加载中 / 还没有计划 / 读取失败 / 有计划。空计划给「导入课程，生成计划」「上传讲义资料」「去对话建立学习目标」；只有失败态才给「重新加载」，并附「去核对接口环境」。
- `currentTask()` 修正：原实现在遍历不到未完成任务时 `return this.plan.tasks[0]`，于是**全部做完**的计划会继续把第 1 项（已完成）当成"立即专注"的对象。现在返回 `null`，页面改说「本次计划已全部完成」，并说明暂未安排项的数量。
- 任务完成判定改用 `appState.isTaskCompleted(taskId, status)`：接口不回写任务状态，完成事实记在本地专注结算里（与 `StudyPlan` 同一口径）。
- 新增 `onPageShow` 强制重读（跳过首帧）：`router.pushUrl` 打开的页返回时**不会**重入 `aboutToAppear`，原实现导入完课程回来仍停在"没有计划"，看起来像导入没生效。
- 已有缓存时提示"当前显示的是最近一次成功读取的计划，可能已过期"，不把旧数据当新的。

### 2.5 前端：计划页同样区分"没有"和"坏了"

`pages/StudyPlan.ets`

- `no_plan` 时标题为「这个账号还没有学习计划」，正文说明计划由真实数据生成，并给「导入课程，生成计划」「去对话建立学习目标」；`error` 保留原有排查文案（地址可访问性）。
- 新增 `onPageShow` 刷新（跳过首帧）、`onPageHide` 复位加载态。

### 2.6 前端：目标卡入口、返回刷新与版本提示

`pages/ChatMain.ets`

- `continueLearningGoal` 增加 `pages/CourseImport` 分支，并携带 `{ initialTab: 'import' }`；`pages/StudyPlan` / `pages/StudyTags` 分支保留（旧后端仍可能返回后者）。
- 新增 `onPageShow` / `onPageHide`：从练习页、导入页、计划页返回时重读目标与工作流状态；离开时复位 `isSending` / `isGoalLoading` —— 进行中的请求会因版本号变化被丢弃，不复位这些标志会让输入框一直处于禁用态。
- `refreshLearningContext` 不再静默吞掉非 404 失败：卡片还在时明确写"上方显示的是上一次读取到的目标"，而不是让过期目标卡继续冒充当前状态。
- 聊天响应缺 `learningContext` 且意图属于 `get_suggestion` / `analyze_weakness` / `analyze_wrong` 时，在回复末尾如实加一句"本次服务端没有返回学习目标，请确认后端已用本仓库当前代码重启；旧服务不返回该字段，系统也不会用演示数据补一个目标"。**不生成假目标来掩盖版本不一致。**

### 2.7 前端：学情画像页的空画像入口

`pages/StudyTags.ets`

- `mastery` 为空时不再只有一句"尚未建立知识画像"，补「导入课程 / 资料」与「去对话建立学习目标」。
- 新增 `onPageShow` 刷新（跳过首帧）与 `onPageHide` 复位：返回时不重读会一直显示空画像。

### 2.8 前端：练习选择器的空态回读

`pages/ExercisePractice.ets`

- 空选择器上唯一的出路是「去上传课程 / 资料」。原实现返回本页时不重读画像，导入完成后仍停在"还没有可练的知识点"，用户只能反复上传。
- `onPageShow` 增加一条窄条件：`showPicker && !practiceFromRoute && result === null && pickerOptions.length === 0` 时重读知识点列表（跳过首帧）。不做无条件刷新，避免覆盖正在答题的界面。

## 4. 新增的前端编译风险（务必先本地构建）

本机无法运行 ArkTS 编译器（第 5 节），以下位置是本轮新写、最需要一次真实构建确认的地方：

1. `@State planKind: string`（`StudySuggestion` / `StudyPlan`）—— 刻意用 `string` 而不是字面量联合类型，避免状态装饰器的类型限制。

5. `StudyTags` 空画像块内新增两个 `Button`，其中一个的 `onClick` 里有两句语句（`setChatPrompt` 后 `pushUrl`）。

若构建报错，优先看这六处；其余改动都是字符串或条件替换。

## 5. 为什么本机没有跑全套

这次改动是在一台**没有开发环境**的机器上做的，如实说明：

- 后端要求 Python ≥ 3.10（`app/domain/profile.py` 用了 `date | str | None` 运行时求值），本机默认 `python` 是 3.8.10；仓库没有随源码交付 `.venv`；`pip install pytest` 因代理不可用而失败（`ProxyError: Cannot connect to proxy`）。→ 无法运行 pytest。
- 系统里另有一个 Python 3.12（uv 管理的裸解释器），但没有 Flask／pytest，同样无法装包；它能加载纯函数模块，所以第 3 节那 12 项检查用它执行。
- 前端需要 DevEco Studio（本机 `D:\develop\DevEco Studio` 不存在），`tools/check_focus_persistence.js` 依赖其内置 `typescript.js`；`oh_modules` 也没有安装。→ 无法转译执行模块，也无法 `assembleHap`。
- 工作区是解压出来的源码目录（没有 `.git`），所以本批改动没有 Git 提交号可引用。

结论：本轮只做了"读源码 + 纯函数执行 + 结构检查"，**没有**形成任何"已通过构建/已通过全套测试"的结论。

## 8. 给验收人的最小复验清单

1. **空账号**：注册（不勾选演示数据）→ 对话说"帮我安排复习" → 目标卡按钮点进去应落在**课程导入页的「导入」标签**，不是学情画像页。
2. **导入后返回**：导入一门课程 → 返回对话 → 目标卡应自动变成「继续本目标练习」（不点"重新加载"）。
3. **学习建议页**：空账号应看到「还没有学习计划」+ 三条入口；把后端停掉再进来，应看到「暂时无法读取学习建议」+「重新加载」+「去核对接口环境」。两种情况文案不能一样。
4. **旧后端兼容**：用 `f22ce66` 那次提交启动后端，对话后应出现"本次服务端没有返回学习目标…"的提示，且**不出现**假目标卡。
5. **接口自检**：`GET /api/v1/workflows/chat/handoff-route-probe` 应为 404，`message` 为 `learning goal not found`（不是 `resource not found`）。
6. **完成态**：把计划里所有任务都结算完成，再进「今日学习建议」，应显示「本次计划已全部完成」，不再出现"立即专注"指向已完成任务。
7. **练习空态回读**：真实账号无知识点 → 进练习页，选择器提示"还没有可练的知识点" → 点「去上传课程 / 资料」导入 → 返回，选择器应出现知识点（不必退出重进）。
