## 二、导入前必须知道的两条规则

1. **导入是“替换”不是“合并”**：课程表导入会替换现有课程列表，DDL 导入会替换现有 DDL 列表。
   所以每类只选一个文件；不要连续导入两个课程文件指望叠加。
2. **同一个合并 JSON 分两次导**：先选「课程」标签导 `11-...json`，再切到「作业 DDL」导同一个文件。
   页面上的类型选择 / 标签页决定用哪个解析器。

## 五、重新给四台模拟器导错题

```powershell
powershell -ExecutionPolicy Bypass -File "演示测试数据\决赛联调-20261105\导入错题到四个模拟器.ps1"
```

默认依次处理 Pura 90 → Mate X7 → MatePad Pro 13 → MateBook Pro：
没有在线设备时自动启动、唤醒解锁、写入相册目录、校验大小并等媒体库索引，再关闭该模拟器。
结果写入 `导入结果-错题.json`。

常用参数：

```powershell
# 只处理其中两台，且导入后不关闭
... 导入错题到四个模拟器.ps1 -Names 'Pura 90','MatePad Pro 13' -KeepRunning

# 模拟器已经手动启动好了，跳过启动/停止
... 导入错题到四个模拟器.ps1 -Names 'Pura 90' -SkipStart -SkipStop

# 想看着模拟器启动
... 导入错题到四个模拟器.ps1 -ShowWindow
```

> 本机模拟器的 `mediatool send` 会报 `create record failed`，
> 所以脚本改用“直接写 MediaLibrary 的 FUSE 相册目录”的方式。
>
> ⚠️ **2026-11-05 实修**：写 FUSE 后必须 `sync` 再关模拟器。
> 不 `sync` 时首次导入看似成功（`stat` 有大小），但模拟器重启后 7 张图会变成
> **0 字节**，App 端表现为「图片读取失败或超过 4MB 上限」。
> 脚本现已内置 `sync` + `mediatool recv` 回读校验；重跑即可修复。
> 若媒体库没索引，打开一次系统「图库」再重跑。

> 冷启动较慢（3–10 分钟），脚本默认等 900 秒。
> 若窗口弹出 `Emulator Freeze`，先关掉模拟器再重试；这是模拟器自身崩溃，不是脚本问题。
