# 香港 ECS 评审实例

公网入口为 `https://47.238.218.213`，健康检查为 `/ready`。Ubuntu 24.04 上由 systemd 管理 Nginx、Gunicorn、PostgreSQL 18、文档 Worker 和 SeaweedFS。应用、数据库和对象存储位于同一台 ECS。数据库和对象存储进程仅监听回环地址，Nginx 提供 API 与有签名的对象访问。

2026-11-13 从公网实测 [服务健康检查](https://47.238.218.213/health) 返回 HTTP 200 和 `{"status":"ok"}`，[就绪检查](https://47.238.218.213/ready) 返回 HTTP 200 和 `{"status":"ready"}`。评审包 1.0.13 默认使用该 HTTPS 地址。[评委联机步骤](../../../评委部署指导/00-云端评审快速开始.md)

| 项目 | 服务器位置 |
| --- | --- |
| 应用和 Python 虚拟环境 | `/opt/zhixue-review` |
| 环境与数据库证书 | `/etc/zhixue-review` |
| 应用和对象存储数据 | `/var/lib/zhixue-review-app`、`/var/lib/zhixue-objects` |
| PostgreSQL | `postgresql@18-main.service`，评审库 `zhixue_review_qa` |
| API 与文档 Worker | `zhixue-app@api.service`、`zhixue-app@worker.service` |
| 私有对象存储 | `zhixue-objects.service` |
| HTTPS 网关 | `nginx.service`，`/etc/nginx/sites-available/zhixue-review` |
| IP 证书 | `/etc/letsencrypt/live/zhixue-review-ip`，Certbot 定时续签后重载 Nginx |

检查服务时在 ECS 执行：

```bash
sudo systemctl is-active postgresql@18-main zhixue-app@api zhixue-app@worker zhixue-objects nginx
curl --fail https://47.238.218.213/ready
sudo journalctl -u zhixue-app@api -u zhixue-app@worker -n 50 --no-pager
```

南京开发库的评审数据需由数据管理同学确认范围后导出。优先在独立评审源库准备获准交接的测试账号和合成数据，再导出 PostgreSQL Custom 格式。云端先恢复到另一份隔离库，核对 Alembic 版本和数据归属后再切换。若导出的记录引用已上传的原文件，需要另行同步对应对象或重新上传。连接凭据、私钥和真实数据库备份通过团队私密渠道交接。
