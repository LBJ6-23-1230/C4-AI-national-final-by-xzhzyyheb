# 学习通知开通步骤（2026-11-03）

这里是给项目开发者的操作说明，普通用户只需要在应用里允许通知。手机系统授权不等于云端推送服务已经开通。

## 当前已有的代码与仍需完成的工作

已实现：客户端通过 Push Kit 获取设备推送标识并绑定账号；服务端保存提醒偏好、生成待办、按免打扰和频率规则安排提醒；独立 `reminder_worker.py` 调用华为接口发送。退出或注销会解除账号设备关联。通知点击目前打开应用首页，再由首页进入任务。

本机检查结果：模型已配置，一次独立哈希表样例生成 3 题成功；`HUAWEI_PUSH_PROJECT_ID`、`HUAWEI_PUSH_JWT_FILE` 均未配置，所以本机后台通知尚不可用。这不能证明手机连接的其他服务器具有相同配置。更新后的界面分别检查服务配置、系统通知权限、设备绑定；配置齐备也不代表已经完成送达验收。

尚未实现服务账号 JWT 的自动签发和续期，现有适配器读取外部维护的 JWT 文件。只放入一次 JWT 不适合长期运行：需要部署团队按官方有效期提前轮换文件。平台错误码完整映射、送达和点击回执、按通知直达业务详情仍需后续接入与真机验证。

## 1. 在华为后台开通 Push Kit

1. 用项目所属开发者账号登录 AppGallery Connect，进入“开发与服务”，选中知学 Mate 对应项目与 HarmonyOS 应用，核对包名 `com.zhixue.mate`。
2. 进入“增长 → 推送服务”，选择“立即开通”，按提示完成数据处理位置设置。
3. 在“项目设置”记录项目 ID。这里填项目 ID，不是客户端 Client ID。
4. 确认应用签名具有 Push Kit 开放能力。手动签名须在开通推送后重新申请调试或发布 Profile 并重新签名；支持的新版本 DevEco 可在自动签名中开通 Push Kit 能力。此前已经能安装的 HAP 不一定具备这项能力。
5. 按实际通知用途申请场景化消息自分类权益，取得允许使用的 `category`。现有代码默认 `MARKETING`，不要把某个未获准分类直接写进配置。

官方依据：[开通推送服务](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/push-config-setting)、[接入流程](https://developer.huawei.com/consumer/cn/doc/doccenter-capabilities/push-gettingstart)。NEXT 的配置流程不应照搬旧版 Android 的 client secret 接口。

## 2. 配置服务端鉴权

1. 按华为[基于服务账号生成鉴权令牌](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/push-jwt-token)创建服务账号、配置授权并保管私钥，按官方示例生成 JWT。不要用手机登录令牌代替。
2. 将生成的 JWT 文本放入只允许服务器读取的文件，例如本机 `E:/private/push.jwt`。不要放进应用资源、Git 或截图。
3. 在 API 和提醒 Worker 使用的同一环境中设置：

```dotenv
HUAWEI_PUSH_PROJECT_ID=你的数字项目ID
HUAWEI_PUSH_JWT_FILE=E:/private/push.jwt
# HUAWEI_PUSH_CATEGORY=按已获准的实际分类设置
```

容器部署时，将 JWT 放在宿主机 `deploy/runtime-secrets/push.jwt`，环境变量中的文件路径改为 `/run/secrets/push.jwt`。项目 compose 已将此目录以只读方式挂载到容器。API 也需要读取它来显示配置状态。

4. 由凭据管理任务在 JWT 过期前生成新令牌，并原子替换 JWT 文件。当前发送器每次读取文件，不需要把 JWT 明文写进环境变量；自动续期任务需要你们部署，仓库没有内置常驻续期器。
5. 重启 API 和提醒 Worker，使环境变量生效。JWT 内容按上述文件轮换。

## 3. 启动提醒 Worker

本机在 `server/zhixue-agent-server`，使用与 API 相同的虚拟环境和 `.env`：

```powershell
.venv/Scripts/python.exe reminder_worker.py --once
.venv/Scripts/python.exe reminder_worker.py
```

`--once` 扫描一轮，第二条保持运行。它独立于 API 和处理资料等任务的普通 `worker.py`，不能漏启动。API 与独立 Worker 共用 SQLite 或 PostgreSQL；不要共用开发用 JSON 文件并行写入。

已有云端部署在相同目录执行：

```sh
docker compose --env-file .env.production up -d api worker reminder-worker
docker compose --env-file .env.production logs --tail=100 reminder-worker
```

数据库 Worker 角色权限和连接预算见 [reminder-worker.md](reminder-worker.md)。

## 4. 在手机上连接与验收

1. 安装已具有推送能力的签名包，登录测试账号，确认手机与 API 网络可达。
2. 在“我的 → 提醒设置”允许系统通知；若提示“此设备尚未连接通知服务”，检查签名能力、网络和 Token 获取情况，再点“重新连接”。应用自动获取并绑定设备标识，无须用户抄 Token。
3. 确认测试账号 `/api/v1/reminder-devices` 返回设备 `active=true`、`hasToken=true`、`permission=true`。接口使用该测试账号的 Bearer 身份；不要在共享日志中输出完整令牌。此接口不下发原始推送 Token。
4. 在提醒设置打开“允许后台通知”，开启相应类别，并选择当前不处于免打扰的时间。保存偏好会实时生效。
5. 使用临近截止的测试任务。常规低优先级建议只留在应用内；首页学习提醒也不会发送手机通知。普通提醒还受每天开始时间、每天最多 2 次、至少间隔 4 小时限制。
6. 退出应用前台，结束专注，等待前台设备心跳过期（约 3 分钟）与 Worker 下一轮扫描（每 30 秒）。分别验证切后台、锁屏、关闭应用的实际表现。
7. 后端投递状态 `accepted` 只表示华为平台接受请求。必须在真实手机看到通知并点击验证，才能记录送达成功；还要验证免打扰、关闭提醒、退出账号后不再收到通知。

## 常见问题

| 现象 | 检查位置 |
| --- | --- |
| 系统权限已开，仍显示服务未开通 | API 的项目 ID 和 JWT 路径、文件可读且非空；与手机实际连接的环境是否一致 |
| 服务有配置，但设备未连接 | 开通后的签名 Profile、Push Kit 开放能力、设备网络、Token 获取及绑定接口 |
| 设备连接成功，但没有发送 | 提醒总开关、类别、实际待办、Worker 是否常驻、免打扰、提醒开始时间、前台/专注状态和发送频率 |
| `authentication_failed` | 项目、服务账号授权、JWT 签名及有效期；私钥和 JWT 不应回传给普通用户 |
| 平台接受但手机未出现 | 真实设备系统通知设置、网络、消息分类权益；需进一步接入平台回执排查 |

这里的“关闭应用后仍接收通知”指由系统推送通道展示通知，不要求应用保持前台，也不是启动一个一直运行的手机后台计时器。
