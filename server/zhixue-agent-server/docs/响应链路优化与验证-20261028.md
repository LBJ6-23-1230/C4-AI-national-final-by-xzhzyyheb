# 响应链路优化与验证

## 实际减少的等待

1. 工作流仅有一个合法下一步，且与原有规则兜底一致时，直接执行该步骤。例如已有画像但没有计划时进入规划、已有计划时进入练习、待提交答案进入评估。多个合法选择仍交给原模型。没有删除诊断、规划、出题、评分、证据和状态版本步骤。
2. 知识库向量请求由逐批串行改为最多三批并发，仍保持每批最多十条、原始顺序与原来的整体时间预算。只有所有向量完整且维度一致才进行语义混合评分；错误继续使用原关键词降级。
3. 对重复文本复用向量，同一批内重复文本也只计算一次。缓存只保存内容摘要与不可变向量，不保存明文资料；配置、密钥、模型或文本变化会换键。缓存限制为 2048 项、15 分钟，仅在内存中，返回副本避免调用者修改缓存。

## 更早且真实的反馈

聊天页和浮动聊天框主动请求 SSE 阶段反馈：接收、读取资料、意图识别、分析、保存、同步计划。只有真实进入阶段才发送。原 JSON 调用路径继续兼容；新客户端也可消费旧服务端 JSON，无需重发请求。

学习计划同步前，已通过既有校验的只读回复可以先显示；卡片、画像更新和最终历史仍在收到完整 result 后执行。图片解析和档案修改不提前暴露未校验 JSON。本次不展示思维链或未校验 token。

服务端后台任务和队列均有界；认证上下文随任务传递；断线不会自动重放写操作。前端处理任意 UTF-8 分包、延迟 dataEnd、错误终态、半途断线与网络句柄释放。既有身份、会话、请求版本校验继续生效。

流式读取上限覆盖多个模型阶段的累计时间，连接超时保持原值。这避免正常生成被过早判为失败，不计入速度提升。Nginx 通过服务端 X-Accel-Buffering: no 关闭此响应的缓冲，并接收每五秒心跳。

## 受控对照数据

运行 `python tools/benchmark_response_latency.py`：每次模拟远程处理固定 50ms，五轮取中位数，逐项断言优化前后结果一致；不访问线上模型。

| 场景 | 原链路 | 优化后 |
| --- | ---: | ---: |
| 30 条文本，3 批向量请求 | 151.428ms | 51.268ms |
| 同一批文本再次编码 | 151.428ms | 0.078ms（缓存） |
| 三个只有唯一合法动作的工作流决策 | 151.549ms | 0.038ms |

这是消除串行等待与重复计算的控制实验，不是线上模型或真机总耗时承诺。收益取决于是否经过对应路径、网络延迟、缓存命中率和负载。自由文本的语义分类仍保留，不承诺所有请求都减半。

## 验证

- 后端回归 754 项通过、1 项 PostgreSQL 集成测试因未配置测试数据库跳过；另 3 项本机 HTTP 多进程集成测试在允许回环连接的环境单独通过。合计 757 项通过，覆盖聊天、学情、工作流、评分幂等、画像更新、鉴权、JSON/SQLite 和检索。
- `test_response_pipeline.py` 使用三线程屏障验证批次真正并发，检查向量顺序、重复文本、缓存失效、非法输出降级；用阻塞模型验证第一条阶段反馈先于模型完成，并检查单次持久化和账号隔离。
- `tools/check_chat_stream.js` 执行真实 ETS 解析器和网络桥，验证 183 种分包尺寸、中文与 emoji、旧 JSON、错误、缺少终态、dataEnd 顺序与缺失时总超时保护、禁止重复 POST 和请求释放。
- `tools/verify_contract_declarations.py` 验证兼容契约及前后端副本一致。
- DevEco ArkTS 编译、debug HAP 打包通过。无签名配置，未安装真机、未部署线上。真实网络与代理上的交互体验仍需部署后采样确认。

测试日志和临时数据未纳入 Git；协议见仓库根目录 `contracts/chat-stream.md`。
